# Документация по шейдер-пакам Bloxd.io

Неофициальное руководство по шейдер-пакам для WebGPU-рендерера Bloxd.io — от создания, реализации, валидации и распространения паков до спецификации API и исследования внутренностей движка.

## Текущая спецификация

- Текущая API: **5** (`pack.json` обязан объявлять `apiVersion: 5`)
- Цель: WebGPU-рендерер
- Последняя проверка: 2026-11-05
- Целевой билд: `bny9u.main.02116121.js` (продакшн, проверен 2026-11-05; preprod отдаёт тот же побайтово идентичный бандл, md5 `60eea80ec48253b7ac6cc45604dc8273` — реестр, заголовок, хуки, лимиты перемерены)
- Шейдерные хуки: 9 (Terrain / Liquid / Model × Vertex / Surface / Light)

Впервые делаете шейдер-пак? Начните с [Начало работы](getting-started/). Смотрите API? — [Справочник по API](api/).

> Эта документация — не официальный ресурс разработчиков игры. Внутренности движка могут меняться с обновлениями — сверяйтесь с целевым билдом и статусом проверки, указанными на каждой странице.
>
> Это руководство создано с помощью ИИ; точность не гарантирована. Проверяйте по реальному поведению в игре. Продолжайте проверять рецепты по экрану загрузчика и компиляции в игре.
>
> Сама функция шейдер-паков — официальная функция, доступная из интерфейса игры, а паки — чистый WGSL (без выполнения JS, без сети), так что с обычным кодом ничего опасного не происходит.

- **[Начало работы](getting-started/)** — обзор, быстрый старт, структура пака, pack.json, 9 хуков, варианты, валидация, распространение. Однодорожечный туториал до вашего первого пака.

- **[Решение проблем](troubleshooting/)** — разбор ошибок по симптомам: загрузка, версия API, компиляция, валидация, варианты, визуальные, текстуры, освещение, модели, производительность.
- **[Внутрянка движка и исследования](internals/)** — пайплайн рендеринга, вызов хуков, заголовок движка, внутренности валидации и компиляции, зарезервированные идентификаторы, внутренности освещения/тумана, сэмплинг и реестр текстур, рендеринг моделей, измеренные данные.
- **[История версий](history/)** — с v1 по v5: изменения по версиям, шаги миграции, удалённые API.

## Метки статуса проверки

Каждая страница указывает свою целевую версию API, билд, дату последней проверки и статус.

| Метка | Значение |
|---|---|
| Verified | проверено на устройстве / на целевом билде |
| Analyzed | подтверждено анализом внутренней реализации |
| Partially Verified | подтверждено лишь частично |
| Experimental | экспериментально / не устоялось |
| Historical | материал для прошлой версии |

Сырые данные, извлечённые из движка (заголовок, реестр, измерения), живут в [Внутрянке движка и исследованиях](internals/); методология и журналы, стоящие за ними, отслеживаются в [журнале исследований](internals/research-log.md).
