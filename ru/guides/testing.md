# Чеклист тестов в игре

> Целевой API: 5 · Целевой билд: `xkg8x` (2026-11-04, прод) · Статус: Verified (портировано на текущий API — рекомендуется перепроверка на устройстве)
Успех компиляции и «хороший вид» — разные вещи. Проверяйте в этом порядке:

1. **Загрузка:** `pack.json` лежит в корне ZIP. Сразу после выбора показывается `Ready. Reload the page to use it.`, и пак становится активным **после перезагрузки страницы**; затем подтвердите `Ready to use`. Сохранённые паки автоматически перепроверяются при следующей загрузке страницы: всякий раз, когда spec-заголовок на стороне движка обновляется, содержимое заголовка сверяется по отпечатку (успех — остаётся как есть / провал — помечается как blocked), так что сломанный старый пак никогда не остаётся тихо активным.
2. **6 вариантов:** без пропусков типовых guard'ов по strict / allow, свет вкл / выкл, террейн / жидкость. Даже если игра использует лишь часть условий, дистрибутивные паки должны исходить из всех 8.
3. **День:** цвета не выжжены по каждому материалу (трава, камень, песок, дерево); естественный контраст светлого/тёмного между верхом и боками.
4. **Ночь:** сравните те же материалы при прежнем дневном свете, в тени и вблизи факелов. Если остаются только освещённые грани — подстройте затухание экспозиции; если темно всё — подстройте защиту локального света.
5. **Вода:** смотрите по отдельности сверху, под скользящими углами, у берегов, из-под воды и ночью. Поведение alpha и подводный вид зависят от композитинга игры — никогда не судите по одной точке обзора. Под водой вуаль из определения жидкости кроет поверх всего (см. [Что могут и чего не могут шейдер-паки](constraints.md#подводная-реальность)), поэтому различия паков видны в основном на поверхности воды и на террейне сквозь вуаль.
6. **Границы и даль:** без выскакивающих волн/узоров на переходах чанков / origin; без двойного тумана и белой дымки вдали.
7. **Производительность:** тяжёлые для фрагмента эффекты с hash/тригонометрией/`pow` — по минимуму. Добавляйте детализацию постепенно и сравнивайте FPS.

## Известные ограничения как предпосылки

- Шейдер-паки ограничены хуками террейна / жидкостей — небо, сущности и UI тем же кодом не обрабатываются.
- Нет входов для добавления карт теней, screen-space-отражений, рефракции, блума и т.д. (глубина сцены разблокирована только для жидкостей как `bloxdOpaqueBehind()` — см. [Функции](../api/functions.md)).
- `bloxdSeconds()` — время анимации без гарантированной связи с днём/ночью игры.
- Нулевой `bloxdSunDirection()` означает, что истинное направление луны неизвестно: это не «лунная физика», а приближение настроения. Направленный лунный свет можно построить из `-bloxdSunDirection()` (только миры с циклом день/ночь — [Солнце и луна](../internals/sun-and-moon.md)).
- `s.position` / `l.position` — локальные координаты, поэтому для эффектов, зависящих от мира, прибавляйте `bloxdRenderOffset()`. А для узоров, локальных внутри блока, локальные координаты — и есть осознанный инструмент.
