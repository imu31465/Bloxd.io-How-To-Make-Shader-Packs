# Что могут и чего не могут шейдер-паки

> Целевой API: 5 · Целевой билд: `ab90qa` (2026-11-03, прод) · Статус: Verified (портировано на текущий API — рекомендуется перепроверка на устройстве)

Потолок реализма шейдер-паков на одной странице: до чего доходит текущий API, что он принципиально не может, что условно, почему существуют эти пределы и какие заменители ближе всего. Прикиньте вид здесь, прежде чем строить его.

## Что может текущий API

- **Цвета, прозрачность и эмиссия, по граням** — три хука `Surface` возвращают цвет (плюс условные альфу и эмиссию) для террейна, жидкостей и моделей
- **Полная пересборка освещения** — три хука `Light` и API освещения (`bloxdShading()` / `bloxdWorldLight()` / `bloxdLitColour()`) выдают собственный рецепт движка в виде компонуемых функций ([Освещение](../api/lighting.md))
- **Тени проекционного стиля, следующие за правками блоков в реальном времени** — `skyLight` — воксельные данные затенения небом; инверсия лифта + пороговый срез превращают их в отчётливые тени под деревьями и крышами ([Тени](shadows.md))
- **Чтение собственных текстур игры** — `bloxdTexel()` сэмплит атлас блочных текстур и текстуры моделей ровно так, как это делает сэмплер движка ([API текстур](../api/texture-api.md))
- **Эффекты на уровне моделей** — `flags` сообщает «это предмет в руке», «это выпавший предмет», «это игрок», «это полублок» ([Флаги](../api/flags.md)); `localPosition` даёт координаты в локальной системе модели ([Структуры](../api/structures.md))
- **Блики зачарования и оверлеи вспышки урона** — `enchantTier` / `enchantColour` / `enchantSpeed` и `overlayColour` читаются и переопределяются ([Эффекты зачарования](../recipes/enchant-effects.md))
- **Время и анимация** — `bloxdSeconds()`, позиция в мире и направление солнца приводят всё в движение ([Время и анимация](../recipes/animation.md))

## Чего не может текущий API

| Вид | Причина |
|---|---|
| Попиксельно точные карты теней (тени, следующие за солнцем, полутень) | На текстуры глубины сослаться нельзя (жидкостный `bloxdOpaqueBehind()` — только геометрия, и как карта теней он непригоден). Затенение лучей света в хуки не подаётся |
| SSAO | Нет доступа к глубине сцены (только запечённая мешером вершинная AO; жидкостная глубина для SSAO непригодна) |
| SSR (отражения) | Цвета сцены нет. Только псевдо-виды с подмесом цвета неба через френель |
| Блум / глэр | Нет хука в постобработку |
| Глубина резкости, хроматическая аберрация, зерно | Требуется полноэкранная постобработка |
| Объёмный свет (god rays) | То же |
| Свои PBR-карты (текстуры normal / roughness / metalness) | Паки не могут добавлять собственные текстуры — API только *читает* существующие текстуры игры через `bloxdTexel()`, и это обычные цветные текстуры без PBR-каналов. Псевдо-PBR-отклик можно лишь оценить по яркости цвета плюс `flags` ([API текстур](../api/texture-api.md)) |
| Подводная рефракция | Цвета сцены нет. Жидкостная глубина (`bloxdOpaqueBehind()`) даёт поглощение по толщине и проекцию дна ([Делаем воду естественной](water.md)) |
| Снятие / изменение подводной вуали (синий тинт) | Вуаль — эмиссивный полноэкранный квад, генерируемый из цвета/альфы определения жидкостного блока, в котором находится камера, и рисуемый вне пайплайнов хуков (самым передним), так что паки не могут менять ни её цвет, ни плотность |
| Прямое подводное детектирование | Ни один вход не сообщает о погружении камеры, а fogStart / fogEnd / fogColour под водой не меняются, поэтому надёжного способа оценить подводность по fogAlpha и т.п. нет |
| Изменение неба, облаков или самого солнечного диска | Хуки выполняются по граням на геометрии террейна / жидкостей / моделей; skybox не входит ни в один пайплайн хуков |

## Условные возможности

- **Вершинная анимация и `discard`** — только в играх, чьё определение несёт `shaderPackPolicy: "allow"`; во всех остальных `BLOXD_STRICT` вырезает эти хуки при компиляции ([Режимы применения по играм](../internals/policy.md))
- **Глубина сцены (`bloxdOpaqueBehind()`)** — только жидкостные хуки, и ей нужен `BLOXD_SCENE_DEPTH`; у хуков террейна и моделей доступа к глубине нет ([Функции](../api/functions.md))
- **`bloxdTexel()` / `bloxdTextureSize()`** — только surface- и light-хуки, и только там, где у пайплайна есть текстура; конфигурации без текстуры компилируют их как стабы, возвращающие белый ([API текстур](../api/texture-api.md))
- **Альфа террейна (`BLOXD_ALPHA`)** — только там, где её определяет вариант ([Варианты и гарды](../getting-started/variants.md))

## Почему эти пределы существуют

Четыре входа, которые понадобились бы «настоящему» постобработочному шейдеру, структурно отсутствуют:

1. **Нет цвета сцены** — хуки выполняются, пока рисуется каждая грань; текстуры фреймбуфера для чтения нет, поэтому SSR, рефракция и всё, что выводится из «что у меня за спиной», вычислено быть не может
2. **Нет глубины сцены** — кроме геометрической пробы `bloxdOpaqueBehind()` только для жидкостей; SSAO и картам теней нужен полный буфер глубины
3. **Нет постобработочной стадии** — после сборки кадра не выполняется ни один хук, поэтому у блума, DOF, аберрации, зерна и god rays нет точки входа
4. **Нет доступа к небу** — skybox, облака и солнечный диск рисуются вне пайплайнов хуков, и ни один вход не описывает их сверх `bloxdSunDirection()`

Подводная вуаль — частный случай той же структуры: это эмиссивный полноэкранный квад, рисуемый самым передним и генерируемый из определения жидкостного блока, внутри которого находится камера, — вне всякого пайплайна хуков.

## Ближайшие заменители

| Желаемое | Ближайший подход со стороны пака |
|---|---|
| Отражения | Взвешенное по френелю смешение к небоподобному цвету + солнечный блик ([Делаем воду естественной](water.md)) |
| PBR-материалы | Оценка спекуляра/шероховатости по яркости + классы материалов по `flags` ([Цвета](../recipes/colors.md), [Реализм](../recipes/realism.md)) |
| Блум / свечение | Выход emission — честно аддитивное свечение, но по граням, а не постобработочное размытие ([Свечение (emission)](../recipes/emission.md)) |
| Ambient occlusion | Запечённая мешером вершинная AO уже есть в `surface.colour`; затемнение по skyLight заодно работает как AO в крупном масштабе ([Тени](shadows.md)) |
| Поглощение по глубине воды | Толщина через `bloxdOpaqueBehind()` + проекция дна в жидкостных хуках ([Жидкости](../recipes/liquids.md)) |
| Подводное настроение | Смиритесь с вуалью; стилизуйте то, что видно сквозь неё (террейн/жидкости и под водой рендерятся штатно) |

## Правда о тенях — «тени деревьев» делаются

В таблице выше невозможны только **следящие за солнцем попиксельно точные карты теней**. Движок считает «тени» с самого начала, и это `skyLight`. LightEngine на стороне меша работает по майнкрафт-образному алгоритму:

1. **Сканирование столбцов**: каждый столбец (x,z) проходится сверху вниз. Свет неба стартует с 15, на непрозрачных блоках становится **0**, затухая при спуске по `lightFilter` (воздух 1 / вода 3 / непрозрачное 15)
2. **BFS-заливка**: растекается вбок на 6 соседей (-1 за блок) — вот что смягчает кромки теней. Сырое значение под окклюзией радиуса r равно (15-r)/15
3. blockLight (факелы и т.п.) — отдельный BFS из 3 RGB-каналов (упаковка в 4 бита)

То есть `l.skyLight` — не просто параметр яркости, а **данные окклюзии воксельного разрешения «видно ли отсюда небо» = карта теней**. Под деревьями, под крышами и в помещениях значение уже численно низкое и приходит сглаженным вершинной интерполяцией. Ставите/ломаете блоки — мгновенный пересчёт = **тени, следующие в реальном времени**. Ванилла использует его лишь «мягко», через `mix(ambient, sky, skyLight)`.

Правильные инструменты — два шага из [Теней](shadows.md) (**восстановить сырые значения инверсией лифта → бинаризовать пороговым `smoothstep`**; `th = 1 - r/15` напрямую задаёт «радиус окклюзии, считаемый тенью») плюс **гейт прямого солнца по небу** (солнце достаёт только туда, где видно небо = суть проекции), скомпонованные с тёплой окраской на солнце / холодной в тени.

**Честные ограничения**: эти тени опираются на «небо сверху», поэтому **со временем за солнцем не вращаются**. Разрешение — поблочное (мягкие кромки — от BFS-рассеивания). Шаблон освещения движка до сих пор содержит закрытый стаб `var shadow: f32 = 1.;` под карты теней (всегда 1.0 = выключен) — читается как след «запланированных» попиксельно точных вращающихся теней. Если попиксельно точные вращающиеся тени кровь из носу нужны, остаются только пути вне API (напр. GLSL-инъекция юзерскриптом, с риском по правилам).

## Подводная реальность

Подводные виды состоят из 3 слоёв:

| Слой | Содержимое | Управляется из паков? |
|---|---|---|
| ① Рендер террейна/жидкости | Обрабатывается хуками. Light-хуки под водой вызываются штатно | Да (работает «под вуалью») |
| ② Вуаль из определения жидкости | Эмиссивный полноэкранный квад из цвета/альфы определения жидкостного блока в позиции камеры, рисуемый самым передним. Игровая настройка `cameraTint` побеждает, если задана | Нет (ни цвет, ни плотность не меняются) |
| ③ cameraTint | Настройка игры | Нет |

Практические пункты: паки продолжают работать под водой / вуаль не снять / по подводности не разветвиться (fogStart / fogEnd / fogColour под водой не меняются, так что fogAlpha её тоже не детектирует).
