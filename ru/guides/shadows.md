# Тени

> Целевой API: 5 · Целевой билд: `ab90qa` · Статус: Verified (поведение LightEngine не менялось со времён замера в v4)

Три способа сделать «тени» в шейдер-паке и их пределы.

## Можно / нельзя

| Эффект | Возможно? | Как |
|---|---|---|
| Отчётливо затемнить под деревьями/крышами (проекционный стиль) | ◎ | инверсия лифта `skyLight` + пороговый срез (ниже) |
| Тени следуют за правками блоков в реальном времени | ◎ | LightEngine пересчитывает мгновенно — автоматически |
| Холодный цвет теней / тёплый на солнце | ◎ | двухцветный сдвиг |
| Тени, вращающиеся за солнцем (карта теней) | ✕ | глубина есть только у жидкостей; затенение лучей света не подаётся на вход |
| Физическая полутень | ✕ | ограничена BFS-рассеиванием на воксельном разрешении |
| AO в реальном времени (SSAO) | ✕ | только AO, запечённая в цвета вершин |

## skyLight — это воксельная карта теней

`l.skyLight` — не просто параметр яркости. LightEngine мешера считает в майнкрафт-образном стиле **воксельные данные затенения «видно ли отсюда небо» — карту теней**:

1. **Сканирование столбцов**: каждый столбец (x,z) сверху вниз; свет неба стартует с 15, на непрозрачных блоках падает в 0, затухает по `lightFilter` (воздух 1 / вода 3 / непрозрачное 15)
2. **BFS-заливка**: растекается по горизонтали на 6 соседей (-1 за блок) — вот что смягчает кромки теней. Сырое значение под окклюдером радиуса r равно (15-r)/15
3. blockLight (факелы) — отдельный BFS из 3 RGB-каналов (упаковка в 4 бита)

Под деревьями, крышами и внутри зданий значение уже низкое и интерполируется плавно по вершинам. Поставили или сломали блок — пересчёт мгновенный — **тени, следующие в реальном времени**.

## Ловушка лифт-кривой

`l.skyLight` приходит **после лифт-кривой** (`y = 1-(1-x/(3-2x))³`, S-кривая, поднимающая тёмные значения):

| Место | Сырой воксель | Поднятое (= l.skyLight) | pow(·, 5.0) |
|---|---|---|---|
| открытое небо | 1.00 | 1.00 | 1.00 |
| под деревом (радиус 2) | 0.87 | **0.97** | **0.86** ← почти цело |
| радиус 3 | 0.80 | **0.92** | 0.66 |
| радиус 5 | 0.67 | 0.78 | 0.29 |

**Это доказанная первопричина того, что «гамма не затемняет тени»** — даже γ=5 опускает 0.97 под деревом лишь до 0.86.

## Фикс: инверсия лифта + пороговый срез

Кривая монотонна и инвертируется точно: `c=(1-y)^(1/3); x=3(1-c)/(3-2c)`. Восстановите сырое значение, затем бинаризуйте **порогом `smoothstep`**. BFS-распространение LightEngine — «-1 за соседний блок», так что `th = 1 - r/15` — это напрямую крутилка «радиус окклюзии, считаемый тенью».

Полная реализация (солнечный гейт + тёплое/холодное разделение + сквозной blockLight) — в [реалистичных рецептах](../recipes/realism.md). Ключевые шаги:

```wgsl
// 1. восстанавливаем сырое значение (пропустите — теней не будет никогда)
let skyRaw = sh_unlift(l.skyLight);
// 2. пороговый срез — на солнце 1 / в тени 0
let sky = smoothstep(shTh - shSoft, shTh + shSoft, skyRaw);
// суть проекции: прямое солнце достаёт только туда, где видно небо
let lit = sunL * sky;
```

Крутилки: **площадь** = `shTh` (0.93→радиус 1.5 / 0.87→2 / 0.80→3 / 0.67→5); **мягкость кромки** = `shSoft`; **темнота ядра** = минимальный ambient и двухточечный сдвиг рассеянного света неба; длинные вечерние тени ≈ `thEff = shTh + 0.10 * (1 - clamp(sunDir.y, 0.0, 1.0))`.

## Честные ограничения

- Тени опираются на **небо сверху**, поэтому **за солнцем не вращаются** (воксельное разрешение; мягкие кромки — от BFS-рассеивания)
- Шаблон освещения движка хранит неиспользуемый `var shadow: f32 = 1.;` (всегда 1.0 = выключен) — правдоподобный след «будущих планов» насчёт попиксельно точных вращающихся теней
- Попиксельно точные вращающиеся тени находятся вне текущего API ([Недостижимые виды](constraints.md))
