# Журнал исследований

> Статус: Analyzed

На этой странице объясняется, как читать технические заметки о реализации игры. Внутреннее поведение не является публичным контрактом API и может меняться при обновлениях игры.

## Принципы исследования

1. **Проверять наблюдаемое поведение** — сопоставлять документацию с проверками в игре и поведением во время выполнения.
2. **Разделять реализацию и API** — отличать функции, доступные шейдер-пакам, от механизмов, используемых только внутри движка.
3. **Указывать источник вывода** — описывать, какая операция движка лежит в основе задокументированного значения или поведения.
4. **Не выдавать предположения за факты** — разделять наблюдения, интерпретации и нерешённые вопросы.
5. **Не путать время проверки со временем выпуска** — проверка в ходе исследования не доказывает, когда функция была распространена.

## Ограничения

- Доступность внутренних функций и структур данных в будущем не гарантируется.
- Структура bundle и внутренние идентификаторы не входят в спецификацию API.
- Используйте документированные API паков вместо зависимости от закрытых деталей реализации.
