# 게임 내 테스트 체크리스트

> 대상 API: 5 · 대상 빌드: `xkg8x` (2026-11-04, 프로덕션) · 상태: Verified (현재 API로 이식됨 — 실기기 재확인 권장)

컴파일 성공과 「보기 좋다」는 별개다. 다음 순서로 확인한다.

1. **읽기:** `pack.json` 이 ZIP 루트에 있을 것. 선택 직후는 `Ready. Reload the page to use it.` 이 표시되고, **페이지 재읽기로 유효화**된다. 재읽기 후 `Ready to use` 가 되는지 확인한다. 한번 저장한 팩은 다음 페이지 읽을 때 자동으로 재검증된다: 엔진측의 사양 헤더가 갱신되면 헤더 내용의 지문 대조가 이루어지고 (합격이면 그대로 / 불합격이면 blocked 표시), 망가진 낡은 팩이 조용히 유효한 채 남는 일은 없다.
2. **6 베리언트:** strict / allow, 조명 on / off, terrain / liquid 각 조건에서 타입 가드 누락이 없을 것. 게임이 일부 조건만 쓰더라도, 배포용 팩은 8가지를 전제한다.
3. **주간:** 풀·돌·모래·목재 등 소재마다 색이 날지 않았는가, 윗면과 측면의 명암차가 부자연스럽지 않은가를 본다.
4. **야간:** 해가 비출 때와 같은 소재, 그림자, 횃불 근처를 비교한다. 밝은 면만 남으면 노출 감쇠, 전부가 어두워지면 국소광 보호를 조정한다.
5. **물:** 바로 위·얕은 시선 각도·기슭·수중·밤을 따로 본다. 알파 거동과 수중 보기는 게임측 합성 방식에 의존하므로, 하나의 시점만으로 판단하지 않는다. 수중은 액체 정의색 베일이 최전면에 걸린다 ([셰이더 팩으로 가능한 것과 불가능한 것](constraints.md#수중의-실상) 참조) — 팩 유무의 차이는 주로 수면과 베일 너머의 지형에서 확인된다.
6. **경계와 거리:** 청크 / 원점 전환으로 파도나 무늬가 튀지 않는가, 원경에서 이중 포그나 흰 안개가 나오지 않는가를 확인한다.
7. **성능:** 해시·삼각 함수·`pow` 를 남용하는 효과는 필요 최소한으로 한다. 디테일을 조금씩 추가해 FPS를 비교한다.

## 알려진 제약을 전제로 한다

- shader pack 은 terrain / liquid 훅에 한정되며, 하늘·엔티티·UI를 같은 코드로 처리하는 구조가 아니다.
- 섀도맵, 화면 공간 반사, 굴절, 블룸 등을 추가하기 위한 입력은 이 API에 없다 (씬 깊이는 액체 한정의 `bloxdOpaqueBehind()` 로 열려 있다 — [함수](../api/functions.md) 참조).
- `bloxdSeconds()` 은 애니메이션용 시간으로, 게임 안의 낮밤과 연동된다는 보장은 없다.
- `bloxdSunDirection()` 이 제로 벡터면 진짜 달의 방향은 알 수 없으며, 파란 환경광을 더하는 처리는 「달빛 물리」가 아니라 분위기를 만드는 근사다. 방향성 달빛은 `-bloxdSunDirection()` 으로 만든다 (낮밤 사이클 월드 한정 — [태양과 달](../internals/sun-and-moon.md) 참조).
- `s.position` / `l.position` 은 로컬 좌표이므로, 월드 위치에 의존하는 효과에서는 `bloxdRenderOffset()` 을 더한다. 블록 안 로컬 무늬를 만들 경우는, 의도적으로 로컬 좌표를 쓸 수도 있다.
