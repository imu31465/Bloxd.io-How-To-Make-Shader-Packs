# 텍스처 팩과의 조합

> 대상 API: 5 · 대상 빌드: `bny9u` (2026-11-05, 프로덕션) · 상태: Verified (현재 API로 이식됨 — 실기기 재확인 권장)

셰이더 팩측에서 텍스처를 추가·샘플링할 수 없다는 제약이 있으므로, 소재 그 자체의 미세한 요철이나 하늘의 화상을 바꾸고 싶으면 셰이더만으로 해결하려 하지 않는다. Bloxd.io용 공개 텍스처팩 리포지토리 [Bloxdy/texture-packs](https://github.com/Bloxdy/texture-packs) 에는 텍스처, skybox, 모델 등을 다루는 별도 방식이 있다.

참고로, 커뮤니티에서 「cinematic shader」로 유통되는 배포물을 해석한 사례에서는, 내용은 텍스처팩 (128x128 텍스처로 `pack.json` / `.wgsl` 을 포함하지 않음) 이었다.

현실적으로는, **셰이더로 빛과 색을 조정하고, 대응하는 별도 리소스팩으로 소재나 하늘을 보완**하는 방침이 좋다. 단, 별도 팩과의 동시 이용 가능 여부나 읽기 순서는 게임측의 구현·설정으로 확인할 것.

텍스처팩 측에도 사양이 있다 (참고): 크기 상한은 base64 변환 후의 JSON 문자열 길이로 25MB이며, PNG의 base64화는 +33% 팽창하므로, 원본 이미지의 합계는 ~18-19MB가 실질 상한이 된다. CSS는 정규식을 이용한 간이 해석으로 처리되므로, 중첩이나 주석은 쓰지 않는다.
