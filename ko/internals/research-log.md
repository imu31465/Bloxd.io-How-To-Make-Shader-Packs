# 리서치 로그

> 상태: Analyzed

이 페이지는 게임 구현에 관한 기술 메모를 읽는 방법을 설명한다. 내부 동작은 공개 API 계약이 아니며 게임 업데이트에 따라 바뀔 수 있다.

## 조사 원칙

1. **관찰 가능한 동작을 확인한다** — 문서의 설명을 게임 내 검증 결과와 런타임 동작에 대조한다.
2. **구현과 API를 구분한다** — 셰이더 팩에서 사용할 수 있는 기능과 엔진 내부에서만 쓰이는 메커니즘을 구분한다.
3. **근거를 설명한다** — 값이나 동작을 기록할 때 어떤 엔진 처리에서 얻은 정보인지 밝힌다.
4. **추론을 사실로 쓰지 않는다** — 관찰한 사실, 해석, 미확인 질문을 구분한다.
5. **관찰 시각을 배포 시각으로 취급하지 않는다** — 조사 중 확인한 시각만으로 기능의 배포 시점을 판단할 수 없다.

## 한계

- 내부 함수와 데이터 구조가 계속 유지된다는 보장은 없다.
- 번들 구성과 내부 식별자는 API 사양의 일부가 아니다.
- 비공개 구현 세부 사항보다 문서화된 팩 API를 사용한다.
