# API v5 마이그레이션 가이드

> 버전: 5 · 상태: Historical (해당 시기의 마이그레이션 가이드; 대상 빌드는 본문에 명시)
대상 빌드: `ab90qa.main.6188124c.js` — **프로덕션과 프리프로드에 동시 적용 (2026-11-03 실측)**, 그리고 두 번들은 다시 바이트 단위로 동일하다 (두 호스트에서 각각 실시간으로 받아 온 메인 번들의 md5 `fc3322212d15be2445c0e8dfc9733fcc`), 따라서 여기 적힌 내용은 그대로 프로덕션에 적용된다. v3 이후 최대의 API 개정이다: 메인 번들은 3.39 MB로 커졌고 (직전 v4 빌드보다 +115 KB), 청크 맵은 195개 id (c0–c195, 알려진 7개 구멍을 제외하면 188개 출력) 이며, 셰이더 파이프라인은 여전히 c51–c56 클러스터에 있다 (로더 c53, 검증기/헤더/레지스트리 빌더 c55, WebGPU/코드젠 c56, 포그 c9) — 단, 기본 팩 템플릿은 c116으로 옮겨갔다 (`tcwczu`에서는 c124였다). 이 레이아웃 세부는 팩에 하나도 보이지 않는다.

*보이는* 것: 엔진 헤더는 6,021에서 **디코딩 8,954 바이트**로 커졌고 (151 → 208 줄) — 거의 모든 구조체가 필드를 얻었으며, 4개의 새 함수가 엔진 자신의 조명 레시피를 문서로 만들었고, `blockFlags` 비트마스크는 사라지고 이름 붙은 불리언들로 이루어진 제대로 된 `BloxdFlags` 구조체가 그 자리를 채웠다. 컴파일 시점 게이트 `#ifdef BLOXD_LIGHTING`도 사라졌다: 조명 상태는 프레임당 uniform의 `lit: u32` 멤버로 옮겨가 `bloxdLit()`로 런타임에 조회한다. 기본 팩 템플릿은 6개가 아니라 **9개 훅 전부**를 싣고 나온다. 그리고 엔진 내부의 `bloxdSp*` 네임스페이스는 27에서 46 심볼로 커졌다.

v5 변경 세트를 한 화면에:

| 영역 | v4 | v5 |
|---|---|---|
| `pack.json` `apiVersion` | `4` (엄격) | **`5` (엄격)** — v4 팩은 로드 시 거부 |
| 블록 식별 | `blockFlags: u32` + 6개 `bloxdBlockFlag*` 비트 상수 | **`flags: BloxdFlags`** — 14개 명명 bool 필드 (§71) |
| 새 flag 종류 | — | **`slab` `stairs` `flat` `placed` `held` `dropped` `thrown` `lifeform`** — 모델과 엔티티를 이제 지형과 구별할 수 있다 (§71) |
| 모델 위치 | — | 모든 입력 구조체에 **`localPosition: vec3f`** (§72) |
| 인챈트·오버레이 | 엔진 전용 | **`enchantTier` / `enchantColour` / `enchantSpeed` / `overlayColour` 입력 + 출력** (§72–§73) |
| 조명 게이트 | `#ifdef BLOXD_LIGHTING` (컴파일 시점, 8 배리언트) | **폐지** — uniform에 `lit: u32` @ 오프셋 4; 런타임에 **`bloxdLit()`**로 검사; 6 배리언트 (§74) |
| 조명 헬퍼 | 엔진 전용 `litColour` | **공개**: `bloxdShading()`, `bloxdWorldLight()`, `bloxdLitColour()` (§74) |
| `bloxdFragmentBlockPosition()` | 헤더에 기재 | **공식 헤더에서는 빠짐** — 그러나 여전히 주입되고 검증기도 여전히 받아 들인다 (§75) |
| 기본 팩 | 6 훅 (vertex+surface) | **9 훅** — light 훅 포함 (§76) |
| `bloxdChunkSize` | 헤더에 없음 | **새 상수 `bloxdChunkSize: i32 = 32`** (§78) |
| `bloxdSp*` 네임스페이스 | 27 심볼 | **46 심볼** (+20, −1) (§79) |
| 텍스처 레지스트리 | 905개 사용 가능 이름 | **896개 사용 가능 이름** — +1, −10 (§80) |
| 로더 제한, zip 규칙, `pack.json` 형태, 훅 이름, strict 계약 | — | **동결, 제한값은 바이트 동일** (§70) |

v4에서의 변환은 대부분 기계적이다 (§77): 이번의 조용한 함정은 모습이 다르다 — `blockFlags`를 여전히 읽거나 light 훅을 `#ifdef BLOXD_LIGHTING`로 가드하는 팩은 **전용 메시지와 함께 검증에 실패**한다 (분석기가 이제 둘 다 설명해 준다), 그래서 조용히 잘못 동작하는 일은 없다; 하지만 옛 비트 상수를 *이름으로만* 읽는 팩은 이식될 때까지 로드를 계속 거부한다. 언제나처럼 배포 전에는 게임 내 컴파일로 확인할 것.

## 69. v4 팩의 운명 (먼저 결론)

**v4 팩 전부 — v4로 배포된 팩도 포함 — 는 이제 프로덕션에서 로드 시점에 정확히 실패한다.** 로더는 `manifest.apiVersion !== 5`를 JavaScript 엄격 비교 `!==`로 판정한다 — 이 빌드에서는 버전 상수 `5`와 헤더 템플릿이 같은 모듈 (모듈 29836) 에 있으므로, 검사와 그 검사가 기준 삼는 헤더 텍스트가 함께 움직인다. JSON은 *숫자* `5`를 담아야 한다; 문자열 `"5"`는 실패하며 v4와 똑같이 JSON 상의 표기 그대로 보고된다.

로드 시점의 두 메시지는 v4에서 불변이며, 라이브 i18n 사전에서 그대로:

> `This pack is for shader pack API version {{packVersion}}. Bloxd supports version {{version}}.` — 키는 존재하지만 5와 같지 않다.

저장된 (이전까지 동작하던) v4 팩은 플레이어에게 아무것도 던지지 않는다: 저장 팩의 판정은 `{kind: "none", reason: "otherApiVersion"}`으로 해결되고, 팩은 조용히 비활성이며, 셰이더 팩 설정 탭은 상태 줄로 이유를 설명한다:

> `This shader pack is for API version {{packVersion}}, so it won't run. Load a version {{version}} pack to replace it.`

manifest 규칙은 그 외에는 재측정했고 불변이다: `pack.json`은 zip 루트에 있는 JSON 객체여야 한다; `apiVersion`은 존재하고 `=== 5`여야 한다; `name`은 필수이며 문자열이고 앞뒤 공백을 제거한 뒤에도 비어 있지 않아야 한다; `author`는 선택이지만 있다면 문자열이어야 한다; manifest의 나머지는 전부 무시된다.

## 70. pack.json, 로더, uniform (불변인 것)

팩 모델 전체가 v4에서 바이트 단위로 이어진다. 로더 제한, 라이브 로더 청크 (c53) 에서 재측정:

| 제한 | 값 | 초과 시 메시지 |
|---|---|---|
| 팩당 `.wgsl` 파일 | 256 | `The pack has more than 256 .wgsl files.` |
| `.wgsl` 소스 합계 | 256 KB | `The pack's .wgsl files are over 256 KB in total.` |
| `pack.json` 크기 | 64 KB | `pack.json is over 64 KB.` |
| zip 크기 | 32 MB | `The zip is over 32 MB.` |
| zip 엔트리 | 1,024 | `The zip has more than 1024 entries.` |
| zip 형태 | — | 분할 zip, Zip64, 암호화 엔트리, 미지원 압축 방식은 각각 전용 메시지로 거부; 모든 파일은 유효한 UTF-8; `pack.json`은 정확히 1개; 경로 중복 불가 |

프레임당 uniform은 여전히 `@group(3) @binding(0) var<uniform> bloxdPackInputs: BloxdPackInputs`, 여전히 64바이트 — 다만 멤버가 하나 늘었다. 레이아웃 표, 라이브 uniform 레이아웃 모듈에서:

| 오프셋 | 필드 | 타입 | 비고 |
|---|---|---|---|
| 0 | `seconds` | `f32` | `bloxdSeconds()`의 기반 |
| 4 | `lit` | `u32` | **v5 신규** — 블록/하늘 조명이 켜져 있으면 1; `bloxdLit()`의 기반 |
| 16 | `renderOffset` | `vec3i` | `bloxdRenderOffset()`의 기반 |
| 32 | `sunDirection` | `vec3f` | `bloxdSunDirection()`의 기반 |
| 48 | `eyePosition` | `vec3f` | `bloxdEyePosition()`의 기반 |

`lit`은 v4가 애초에 `seconds`와 `renderOffset` 사이에 두고 있던 패딩에 끼어 들어갔다 (v4에서 오프셋 4–15는 정렬 여유였다; `renderOffset`이 16에 머무는 것은 `vec3i`가 16바이트 정렬을 필요로 하기 때문이다), 그래서 구조체의 총 크기와 다른 모든 멤버의 오프셋은 그대로다. 엔진은 이것을 단 한 줄 `setUint32(4, lit ? 1 : 0)`로 쓴다 — 라이트 레벨이 아니라 플래그다: v4의 JS 측 이름 `terrainLightLevels` / `terrainHeldLight`는 번들에서 완전히 사라졌다.

팩 바인드 그룹 레이아웃은 그 외에는 불변이다: 그룹 3은 여전히 `0` uniform · `1` 씬 깊이 텍스처 (액체 배리언트) · `2` `bloxdSpTextureLayers` 스토리지 버퍼. `minBindingSize`도 여전히 64.

## 71. flags 재작성: `blockFlags` → `BloxdFlags` (헤드라인)

v4는 면을 `blockFlags: u32`와 여섯 `bloxdBlockFlag*` 상수 (opaque 1, emissive 2, vegetation 4, dirt 8, sand 16, rock 32) 로 식별했다. v5는 그 메커니즘 전체를 명명 불리언의 구조체로 바꾼다, 라이브 헤더에서 그대로 인용:

```wgsl
// What kind of block, item or lifeform a face is. Any number of flags may be
// set, possibly even none. For example, sandstone is sand and rock.
struct BloxdFlags {
    opaque: bool,     // Opaque blocks, i.e. full cubes with no gaps or holes.
    emissive: bool,   // Blocks that emit light, e.g. lava and glowing ores.
    vegetation: bool, // Leaves, grass blocks and leafy plants, e.g. tall grass.
    dirt: bool,       // Soil, grass blocks included. Rocky Dirt is rock too.
    sand: bool,       // Sand, Red Sand and every sandstone, which is rock too.
    rock: bool,       // Stone variants, and more, e.g. gravel, ores and magma.

    // Drawn as block models, so never part of terrain or flagged as opaque.
    slab: bool,       // Half blocks.
    stairs: bool,     // Stairs and corner stairs.
    flat: bool,       // Planes, e.g. tall grass, flowers, crops and cobwebs.

    placed: bool,     // Blocks placed as part of chunks. Not items or vehicles.
    held: bool,       // Items in a hand, in first or third person.
    dropped: bool,    // Dropped items, on the ground, on a belt or in a pipe.
    thrown: bool,     // Items in flight, e.g. snowballs, arrows and rockets.

    lifeform: bool,   // Players, mobs and NPCs. Includes armour and cosmetics.
}
```

여섯 개의 v4 비트 검사는 필드에 하나하나 대응된다 — 이번 이식은 재사고가 아니라 개명이다:

| v4 | v5 |
|---|---|
| `(surface.blockFlags & bloxdBlockFlagOpaque) != 0u` | `surface.flags.opaque` |
| `(surface.blockFlags & bloxdBlockFlagEmissive) != 0u` | `surface.flags.emissive` |
| `(surface.blockFlags & bloxdBlockFlagVegetation) != 0u` | `surface.flags.vegetation` |
| `(surface.blockFlags & bloxdBlockFlagDirt) != 0u` | `surface.flags.dirt` |
| `(surface.blockFlags & bloxdBlockFlagSand) != 0u` | `surface.flags.sand` |
| `(surface.blockFlags & bloxdBlockFlagRock) != 0u` | `surface.flags.rock` |

여덟 개의 **새** 필드가 진짜 이야기다. v4는 반 블록과 온전한 블록을, 손에 든 아이템과 지형을, 플레이어와 호박을 구별할 방법이 없었다 — 지형이 아닌 모든 면은 그저 「불투명 아님」에 텍스처 id가 붙은 것에 지나지 않았다. v5는 「지금 보고 있는 것이 무엇인가」에 직접 답한다:

- **`slab` / `stairs` / `flat`** — 3가지 블록 모델 형태. `flat`은 교차면 식물 (잔디, 꽃, 작물, 거미줄) 을 덮는다. 이것들은 *블록 모델로 그려지므로*, 헤더의 주석대로 지형에 속하는 일도 `opaque`로 플래그되는 일도 없다.
- **`placed`** — 청크의 일부로 세계에 놓인 지오메트리; 명시적으로 아이템이나 탈것이 *아니다*.
- **`held`** — 손에 든 아이템, 1인칭·3인칭 모두. v1부터 1인칭 셰이더 작가가 바라던 필드다: 든 아이템을 검출해서 세계와 다르게 취급할 수 있게 됐다.
- **`dropped`** / **`thrown`** — 땅 위/벨트 위/파이프 안의 아이템 대 (눈덩이, 화살, 로켓처럼) 날아가는 아이템.
- **`lifeform`** — 플레이어, 몹, NPC, *방어구와 코스튬 포함*.

`localPosition` (§72) 과 인챈트/오버레이 입력과 결합하면, 모델 파이프라인은 이제 자신이 무엇을 렌더링하고 있는지 완전히 알고 셰이딩할 수 있다. v4에서는 불가능했던 최소의 「든 아이템 발광」 레시피:

```wgsl
fn bloxdModelSurface(surface: BloxdSurfaceIn) -> BloxdSurface {
    var out = bloxdDefaultSurface(surface);
    // Brighten whatever the local player is holding, nothing else.
    if (surface.flags.held) {
        out.colour *= 1.15;
    }
    return out;
}
```

바뀌지 *않은* 것도 적어 두자: 필드는 세 입력 구조체 모두 같은 자리에 있다 (`BloxdVertexIn`, `BloxdSurfaceIn`, `BloxdLightIn` — 필드명 `flags`, 타입 `BloxdFlags`), 살아남은 여섯 불리언의 시맨틱은 헤더가 이제 명시하는 같은 예외를 딴 v4 시맨틱이고 ("Rocky Dirt is rock too", "every sandstone is rock too"), 여러 플래그는 여전히 자유롭게 결합된다 ("sandstone is sand and rock", "possibly even none").

## 72. 새 입력: `localPosition`, 인챈트 4중항, 그리고 `overlayColour`

`BloxdVertexIn`, `BloxdSurfaceIn`, `BloxdLightIn` 모두 같은 새 멤버를 얻는다. 헤더에서 그대로:

```wgsl
    localPosition: vec3f, // A model's local coordinates. 0 for terrain/liquid.
```

- **`localPosition`** — 모델 인스턴스가 세계에 놓이기 전의, 버텍스/프래그먼트의 모델 공간 좌표. 지형과 액체 면에서는 `vec3f(0.0)` (모델이 없다). 플레이어의 팔, 손에 든 검, 풍차의 날개 — 모델과 함께 회전하는 좌표는 이것이며, 「검의 어느 위치인가」에 건 모델별 애니메이션이나 만곡 효과는 월드 공간 추측 대신 필드 하나로 쓴다. light 구조체에서 헤더는 이것이 "the same as in BloxdVertexIn, after the vertex hook" — 즉 버텍스 훅이 버텍스를 옮기면 light 훅의 `localPosition`이 따라간다고 적고 있다.

그리고 `BloxdSurfaceIn` / `BloxdLightIn` 에만 (버텍스 구조체에는 필요 없다):

```wgsl
     // Enchanted items and armour only, all 0 for anything else.
     enchantTier: u32,     // 1-5 for Tier 1-5.
     enchantColour: vec4f, // RGB enchant colour, and its animated alpha.
     enchantSpeed: f32,    // How fast the pattern moves, faster at higher tiers.

     // Players and mobs only, 0 for anything else: RGB overlay colour, e.g. the
     // red flash when hurt, and its alpha. bloxdLitColour mixes it into colour.
     overlayColour: vec4f,
```

- **`enchantTier`** — 아이템의 인챈트 티어를 정수 1–5로. 색을 파싱하지 않고 고전적인 「티어별 글린트 세기」를 만들 수 있다.
- **`enchantColour`** — 살아 있는 인챈트 RGB와, `.a`에 그 *애니메이션되는* 알파: 엔진이 글린트 스윕을 움직여 주므로, `.a`를 프래그먼트마다 읽으면 움직이는 패턴을 공짜로 얻는다. 인챈트 안 걸린 면에서는 전부 0.
- **`enchantSpeed`** — 인챈트 패턴이 움직이는 속도; 헤더 자신의 주석은 "faster at higher tiers" — `enchantTier`와 `enchantSpeed`는 구성상 일치한다.
- **`overlayColour`** — 피해/피격 플래시 등의 엔티티 오버레이 (RGB + 알파), 플레이어나 몹이 아닌 것에는 0. 엔진은 이것을 조명 *이전에* 혼합한다; 출력 쪽은 §73.

낡은 4중항 (`textureId`, `textureRotation`, `uv`, `mipLevel`) 은 그대로 이어지고, 주석만 다시 쓰였다: v4는 `uv`를 "texture coordinates in blocks"라 했고 v5는 "The texture spans 0-1. `fract(uv)` is drawn."라 한다 — 같은 필드를 텍스처 관점에서 기술한 것이다: 텍스처 타일 하나가 uv의 `0.0–1.0`에 펼쳐지고, uv의 정수 스텝이 반복되는 벽에 타일을 깐다. 여러 블록에 걸친 폭에 대한 자체 가정을 굴리지 않는 한 이식할 것은 없다.

## 73. 새 출력: `BloxdSurface`가 `enchantColour`와 `overlayColour`를 얻다

surface **출력** 구조체는 필드가 두 개 자란다, 그대로:

```wgsl
struct BloxdSurface {
    colour: vec3f,        // RGB colour output.
#ifdef BLOXD_ALPHA
    alpha: f32,           // Opacity output.
#endif
    emission: vec3f,      // Emissive RGB, added after lighting, before fog.
    enchantColour: vec4f, // Enchant output, mixed in by bloxdLitColour.
    overlayColour: vec4f, // Overlay output, mixed in by bloxdLitColour.
}
```

이제 당신의 surface 훅이 인챈트 글린트와 피격 플래시를 맡는다, emission을 이미 맡고 있던 것과 같은 방식으로:

- `bloxdDefaultSurface`는 `surface.enchantColour`와 `surface.overlayColour`를 변형 없이 통과시키므로, 기본 겉모습은 v4의 엔진 측 거동과 동일하다.
- 훅에서 **`out.enchantColour`를 0으로 만들면** 커스텀 조명에서 인챈트 글린트가 빠진다 — 「글린트 없는 리얼리즘」 팩이 이제 두 줄이다.
- **`out.overlayColour.a`를 증폭하면** 베이스 색을 건드리지 않고 피격 플래시를 더 강하게 만든다; 혼합은 `bloxdLitColour` (§74) 에서, 셰이딩 뒤에, 엔진이 두었던 바로 그 자리에서 일어난다.
- emission 순서 주석은 그대로 이어진다: emission은 *조명 뒤, 포그 앞에 가산*된다 — 그리고 새 두 필드는 `bloxdLitColour`가 *혼합*하며, 그것은 emission과 포그의 *앞*이다. 전체 출력 사슬을 순서대로: `colour` → 오버레이 혼합 → 셰이딩 → 인챈트 혼합 → 월드 라이트 → `+ emission` → 포그.

## 74. 조명 레시피의 공개: `bloxdLit()`와 세 헬퍼

v4는 조명 코드를 컴파일 시점에 게이트했다: 8 배리언트 (`strict|allow` × `lit|unlit` × `terrain|liquid`), `#ifdef BLOXD_LIGHTING`이 light 훅이 lit 경로와 unlit 경로 중 어느 쪽을 달릴지 결정했다. v5는 조명 축을 컴파일에서 통째로 뺀다:

- **배리언트 행렬은 8이 아니라 6**: `strict|allow` × `terrain|liquid|model`, 이름은 `allow.terrain` … `strict.liquid` 등 (엔진 자신이 로더 화면을 위해 만드는 라벨).
- `BLOXD_STRICT`는 여전히 strict 전용; `BLOXD_ALPHA`는 여전히 모든 액체와 모든 allow 배리언트 (strict 지형과 strict 모델에서는 off); `BLOXD_SCENE_DEPTH`는 여전히 액체 전용. **`BLOXD_LIGHTING`는 더 이상 존재하지 않는다.**
- 조명 상태는 uniform (`lit: u32`, §70) 으로 옮겨갔고 코드에서는 새 헤더 함수로 조회한다:

```wgsl
// Whether block and sky lighting is on. When it's off, BloxdLightIn's
// blockLight and heldLight are 0, and its skyLight and light colours are 1.
fn bloxdLit() -> bool {
    return bloxdPackInputs.lit != 0u;
}
```

v4 팩이 light 훅을 `#ifdef BLOXD_LIGHTING ... #else ... #endif`로 감쌌다면, v5 이식은 얼리 리턴이다: `if (!bloxdLit()) { return bloxdDefaultLight(surface, light); }`. 분석기가 이것까지 알려 준다 — `BLOXD_LIGHTING`를 쓰면 이제 *"BLOXD_LIGHTING was removed in apiVersion 5; test bloxdLit() in code instead."* 라는 검증 메시지가 나온다 (라이브 검증기에서 그대로 실측).

헤더에 함수가 셋 더 합류하고, 그것은 v4 작가들이 손으로 다시 유도하곤 하던 것들이다 — 엔진 자신의 조명이, 호출 가능한 WGSL로 문서화되어:

```wgsl
// How the face's material and angle light it: directional light on its
// diffuse colour, plus its emissive and ambient terms, clamped to 0-1.
fn bloxdShading(light: BloxdLightIn) -> vec3f {
    let diffuse = light.directional * light.diffuse;
    return saturate(diffuse + light.emissive + light.ambient);
}

// The world's light at this fragment: the brightest of block, sky and held
// light, none below ambientLightColour.
fn bloxdWorldLight(light: BloxdLightIn) -> vec3f {
    let ambientLight = light.ambientLightColour;
    let blockLight = ambientLight + light.blockLight * (1.0 - ambientLight);
    let skyLight = mix(ambientLight, light.skyLightColour, light.skyLight);
    let heldLight = ambientLight + light.heldLight * (1.0 - ambientLight);
    return max(max(blockLight, skyLight), heldLight);
}

// The surface's colour lit as the engine does, before emission and fog:
// mixed with overlayColour, then bloxdShading, then mixed with
// enchantColour, then bloxdWorldLight.
fn bloxdLitColour(surface: BloxdSurface, light: BloxdLightIn) -> vec3f {
    let overlay = surface.overlayColour;
    let overlaid = mix(surface.colour, overlay.rgb, overlay.a);
    let shaded = bloxdShading(light) * overlaid;
    let enchant = surface.enchantColour;
    let enchanted = mix(shaded, enchant.rgb, enchant.a);
    return max(enchanted * bloxdWorldLight(light), vec3f(0.0));
}
```

그리고 `bloxdDefaultLight` 자신이 이제 그것들을 쓴다 — 기본값은 문자 그대로 「엔진 레시피를 적용하고, emission을 더한 결과에 포그를 입힌다」이다:

```wgsl
fn bloxdDefaultLight(surface: BloxdSurface, light: BloxdLightIn) -> BloxdLight {
    let lit = bloxdLitColour(surface, light);
    return BloxdLight(bloxdApplyFog(lit + surface.emission, light));
}
```

`bloxdShading`에 값을 먹이려고 `BloxdLightIn`도 입력을 두 개 얻는다 (주석 그대로):

```wgsl
    directional: f32,  // Summed Lambert from directional lights; 0 if none.
    diffuse: vec3f,    // The material's RGB response to directional light.
    emissive: vec3f,   // The material's RGB glow, added to directional light.
```

`diffuse`와 `emissive`는 v5의 신규다 (v4에는 `directional`과 `ambient`만 있었다): 엔진이 이미 아는 머티리얼 응답을 잃지 않고, `bloxdShading`을 개조해 재구축할 수 있게 해 준다 — 이를테면 엔진의 월드 라이트는 유지하면서 램버트 항만 자신의 랩어라운드 셰이딩으로 바꾸는 식이다. 라이트 레벨의 문서 주석도 "0 without BLOXD_LIGHTING"에서 "0 when !bloxdLit()"로 다시 쓰였는데, 같은 사실을 v5 어휘로 말한 것이다.

「커스텀 셰이딩 + 엔진 월드 라이트」 light 훅 — v4 작가들이 `litColour`를 스케일해서 근사하던 레시피가 이제 정확해진다:

```wgsl
fn bloxdTerrainLight(surface: BloxdSurface, light: BloxdLightIn) -> BloxdLight {
    // Half-Lambert wrap: soft, never fully dark on the back face.
    let nDotL = light.directional; // already the summed Lambert term
    let wrapped = nDotL * 0.5 + 0.5;
    let shaded = saturate(wrapped * light.diffuse + light.emissive + light.ambient);
    let colour = max(shaded * bloxdWorldLight(light), vec3f(0.0));
    return BloxdLight(bloxdApplyFog(colour + surface.emission, light));
}
```

## 75. 제거: `bloxdFragmentBlockPosition()`, `bloxdBlockFlag*`, `bloxdSpLitColour`

세 가지가 사라졌고, 검증기는 이름을 들어 말해 준다:

- **`bloxdFragmentBlockPosition(position, normal) -> vec3i`** — 공식 헤더에서는 빠졌지만, **실제로 죽은 것은 아니다**: 검증기의 서명 테이블은 항목을 유지하고 있고 (그래서 호출은 버텍스 훅을 포함한 모든 훅에서 여전히 검증을 통과한다), 코드 제너레이터는 terrain/liquid 모듈과 두 모델 프로그램 모두에 여전히 정의를 주입한다 (terrain/liquid용은 `vec3i(floor(position - normal * 0.5)) + bloxdRenderOffset()`, 모델용은 1/64 오프셋에 셀 스냅하는 변형). 이것을 호출하는 v4 팩은 계속 동작한다. 폐기 예정으로 취급할 것: 이제 문서화되어 있지 않으므로 연속 위치에는 `bloxdWorldPosition()`을, 「어느 블록 위인가」에는 `flags`를 쓰고, 장래 버전에서 사라질 수 있음을 예상하라.
- **여섯 `bloxdBlockFlag*` 상수** — `BloxdFlags` (§71) 로 대체됐다. 살아남은 참조는 분석기의 예약 이름 진단과 함께 검증에 실패한다.
- **`bloxdSpLitColour`** — 그 일자리가 공개 `bloxdLitColour()` (§74) 가 된 엔진 내부 심볼. `bloxdSp*` 네임스페이스를 떠난다 — 그 외의 네임스페이스는 자라기만 한다 (§79).

변화 없이 살아남는 v4 시대 함수들: `bloxdEyePosition()`, `bloxdRenderOffset()`, `bloxdSunDirection()`, `bloxdSeconds()`, `bloxdWorldPosition()`, `bloxdApplyFog()`, `bloxdDefaultVertex()`, `bloxdDefaultSurface()`, `bloxdDefaultLight()`, 텍스처 API 전체 (`bloxdTexel`, `bloxdTextureSize`, `bloxdTextureId*` — §79가 레지스트리를 재측정한다), 그리고 액체 배리언트 시맨틱을 그대로 가진 `BloxdOpaqueBehind` / `bloxdSceneDepth`.

## 76. 기본 팩이 아홉 훅 전부를 싣고 나온다

새 팩의 출발점이 되는 템플릿에 이제 light 훅이 포함된다 — v4 템플릿은 6개 (프로그램당 vertex+surface) 였고 light 훅은 문서에서 복사해야 했다. v5의 것, 그대로 완전하게 (출시 형태 1,683 바이트):

```wgsl
// Every hook here returns its engine default. Modify the return values to start
// building a shader pack. If you delete a hook, the default is used instead.

// All blocks but water and block models use terrain hooks.
#ifndef BLOXD_STRICT
// Strict games keep terrain where it is. Without the #ifndef, this hook would
// turn the whole shader pack off there.
fn bloxdTerrainVertex(vertex: BloxdVertexIn) -> BloxdVertex {
    return bloxdDefaultVertex(vertex);
}
#endif

fn bloxdTerrainSurface(surface: BloxdSurfaceIn) -> BloxdSurface {
    return bloxdDefaultSurface(surface);
}

fn bloxdTerrainLight(surface: BloxdSurface, light: BloxdLightIn) -> BloxdLight {
    return bloxdDefaultLight(surface, light);
}

// Water uses liquid hooks. To share code with another hook, define a function
// and call it from both places.
#ifndef BLOXD_STRICT
fn bloxdLiquidVertex(vertex: BloxdVertexIn) -> BloxdVertex {
    return bloxdDefaultVertex(vertex);
}
#endif

fn bloxdLiquidSurface(surface: BloxdSurfaceIn) -> BloxdSurface {
    return bloxdDefaultSurface(surface);
}

fn bloxdLiquidLight(surface: BloxdSurface, light: BloxdLightIn) -> BloxdLight {
    return bloxdDefaultLight(surface, light);
}

// Models: block models such as slabs and plants, items, players and mobs.
#ifndef BLOXD_STRICT
fn bloxdModelVertex(vertex: BloxdVertexIn) -> BloxdVertex {
    return bloxdDefaultVertex(vertex);
}
#endif

fn bloxdModelSurface(surface: BloxdSurfaceIn) -> BloxdSurface {
    return bloxdDefaultSurface(surface);
}

fn bloxdModelLight(surface: BloxdSurface, light: BloxdLightIn) -> BloxdLight {
    return bloxdDefaultLight(surface, light);
}
```

주석은 새 문장이고, 삭제 모델의 문서로서 읽을 가치가 있다: *"Modify the return values to start building a shader pack. If you delete a hook, the default is used instead."* 액체 주석도 바뀌었다 — v4는 "If deleted, water uses your terrain hooks instead"라 했고, v5는 "To share code with another hook, define a function and call it from both places" — 그리고 strict 주석은 이제 `#ifndef`를 한 문장으로 설명한다: *"Strict games keep terrain where it is. Without the #ifndef, this hook would turn the whole shader pack off there."*

strict 게임 계약 자체 (v4 §60) 는 불변이다: 가드 없는 버텍스 훅은 `<hook> moves terrain, which strict games prevent.`를, 도달 가능한 `discard`는 `discard makes terrain see-through, which strict games prevent.`를 보고하고, 어느 쪽이든 strict 게임에서 *모든* 훅을 비활성화한다. 12개 allow 타이틀은 라이브 번들에서 재측정했다 — 여전히 12개, 불변.

## 77. v4 → v5 마이그레이션 체크리스트

1. **`pack.json`**: `"apiVersion": 5` — 문자열이 아니라 숫자.
2. **flags 이식** (기계적, §71): 모든 `blockFlags & bloxdBlockFlagX != 0u` → `flags.x`; 상수는 삭제 — 검증기가 이름으로 거부한다.
3. **조명 게이트 이식** (검증기 메시지가 있는 것): `#ifdef BLOXD_LIGHTING` → `if (bloxdLit()) { ... } else { return bloxdDefaultLight(surface, light); }`; `BLOXD_LIGHTING`는 이제 *"BLOXD_LIGHTING was removed in apiVersion 5; test bloxdLit() in code instead."*를 촉발한다.
4. **`bloxdFragmentBlockPosition`에서 벗어나기** (§75) — 여전히 컴파일되지만 이제 문서화되어 있지 않다; `bloxdWorldPosition()` / `flags`를 쓸 것.
5. **새 입력/출력 결정** *(임의)*: `flags.slab/stairs/flat/placed/held/dropped/thrown/lifeform` (§71), `localPosition` (§72), 인챈트 4중항 + `overlayColour` (§72–§73). `bloxdDefaultSurface` 경유의 통과는 v4 겉모습을 정확히 유지한다.
6. **엔진 레시피 헬퍼 채택** *(임시이지만 권장)*: 손으로 굴린 라이트 색을 `bloxdLitColour(surface, light)`로 대체 — 또는 `bloxdShading` / `bloxdWorldLight`와 섞어 맞추고 (§74) — 그다음 `bloxdDefaultLight`가 하듯 `surface.emission`과 `bloxdApplyFog`를 더한다.
7. **strict 감사** (v4에서 불변): 버텍스 훅과 도달 가능한 모든 `discard`에 `#ifndef BLOXD_STRICT`.
8. **게임 내 컴파일 확인**: 로더는 **6** 배리언트 전부를 한 번에 검증한다 (strict × terrain/liquid/model — 조명 축은 더 이상 따로 컴파일되지 않는다, §74). 그리고 allow 게임 하나와 strict 게임 하나를 눈으로 확인한다.
9. **자신의 버전 메타데이터를 올리고 재배포**: 플레이어 기계에 저장된 v4 사본은 조용히 비활성이며 (§69), 이유를 말해 주는 것은 설정 탭뿐이다.

### 77.1 완전한 v4 → v5 이식, 전과 후

간결한 v4 팩 — 「초목 틴트 + 헬드라이트 부스트」 — 오늘날이라면 실패하는 그대로의 모습과, 이식된 모습:

```wgsl
// ---- v4 (fails validation on ab90qa) ----
fn bloxdTerrainSurface(surface: BloxdSurfaceIn) -> BloxdSurface {
    var out = bloxdDefaultSurface(surface);
    if ((surface.blockFlags & bloxdBlockFlagVegetation) != 0u) {
        out.colour *= vec3f(1.0, 1.08, 0.9);
    }
    if ((surface.blockFlags & bloxdBlockFlagEmissive) != 0u) {
        out.emission += vec3f(0.05);
    }
    return out;
}

#ifdef BLOXD_LIGHTING
fn bloxdTerrainLight(surface: BloxdSurface, light: BloxdLightIn) -> BloxdLight {
    var out = bloxdDefaultLight(surface, light);
    out.colour += light.heldLight * 0.15; // glow near a held light source
    return out;
}
#endif
```

```wgsl
// ---- v5 (ported; identical on-screen behaviour) ----
fn bloxdTerrainSurface(surface: BloxdSurfaceIn) -> BloxdSurface {
    var out = bloxdDefaultSurface(surface);
    if (surface.flags.vegetation) {
        out.colour *= vec3f(1.0, 1.08, 0.9);
    }
    if (surface.flags.emissive) {
        out.emission += vec3f(0.05);
    }
    return out;
}

fn bloxdTerrainLight(surface: BloxdSurface, light: BloxdLightIn) -> BloxdLight {
    if (!bloxdLit()) { return bloxdDefaultLight(surface, light); }
    var out = bloxdDefaultLight(surface, light);
    out.colour += light.heldLight * 0.15;
    return out;
}
```

그리고 같은 팩이 이제 더할 수 있는 v5 전용 보너스 — 모델 인식 두 줄:

```wgsl
fn bloxdModelSurface(surface: BloxdSurfaceIn) -> BloxdSurface {
    var out = bloxdDefaultSurface(surface);
    if (surface.flags.lifeform && !surface.flags.held) {
        out.colour *= 1.05; // subtle world-entity lift, hands excluded
    }
    return out;
}
```

## 78. 그 외의 v5 변경과 메모

- **`bloxdChunkSize`가 헤더에 합류** — `const bloxdChunkSize: i32 = 32;` ("Blocks along each side of a chunk"). 그동안 엔진 쪽 매직 넘버였던 것이, 이제 분기에 쓸 수 있는 명명 상수다. `bloxdPi`/`bloxdTau`는 불변.
- **헤더의 프레임 함수 절에 공유 주석이 붙었다** — "These functions return the same value for the entire frame" (v4: "return 1 value per frame, the same for every call site") — 순수하게 문구 차이.
- **Y 도함수는 팩 코드에서 자동으로 부호 반전된다.** 분석기는 `dpdy`, `dpdyCoarse`, `dpdyFine` 호출을 모두 `(-dpdy(...))`로 다시 쓴다 — 스크린 공간 y축은 아래를 향하므로, 반전이 「위쪽으로 갈 때의 변화율」을 직관에 맞춰 준다. `dpdy(h)`를 「높아질 때 h가 어떻게 변하나」로 쓰면, 출력된 코드가 대신 부호를 뒤집는다. `dpdx`와 `fwidth` 패밀리는 무손상. (검증기의 토큰 재작성 패스에서 실측; dpdy 패밀리가 특별히 반전 집합으로 지정되어 있다.)
- **텍스처 이름 진단에 철자 엔진이 붙었다.** `bloxdTextureId`로 시작하지만 해석되지 않는 이름은 이제 레벤슈타인 기반 제안을 받는다: *"`X' isn't part of the shader pack API. Texture names start with exactly bloxdTextureId: did you mean bloxdTextureIdY?`"* — 프레임 표기 (*"names a frame of the animated texture Z: use bloxdTextureIdZ, which bloxdTexel animates."*) 와 회전 표기 (*"names a turned copy of Z: use bloxdTextureIdZ, which bloxdTexel turns as each face shows it."*) 에도 전용 메시지가 있다. 일반 예약 규칙이 진단에 재진술되어 있다: *"Packs can't declare names starting with bloxd, other than the hook functions bloxd<Terrain|Liquid|Model><Vertex|Surface|Light>"*, 그리고 *"Packs can't use X: the engine binds every texture and sampler. Surface and light hooks can read atlas textures with bloxdTexel."*
- **참조된 텍스처 상수만 출력된다.** 헤더의 `bloxdTextureId*` 블록은 실제로 참조한 이름으로 팩마다 생성된다 — 상수 3개를 쓰는 팩에는 3줄의 `const`가 앞에 붙고, 약 900줄 전체가 아니라.
- **`HEADER_VERSION`가 `9.<hash>.<hash>`로 이동** — v4와 같은 이중 접미사 구조 (헤더 재료의 fnv1a32, 정렬된 이름-id 레지스트리의 fnv1a32), 선행 정수만 8에서 9로. 저장 팩 재검사 논리 ([v4 마이그레이션 가이드](v4.md)의 §55) 는 불변: 헤더/레지스트리가 바뀌면 저장 팩이 「재확인 필요」로 넘어간다.
- **i18n 면**: 셰이더 팩 키 패밀리는 형태가 불변 (v4 가이드 §62의 `load*`, `status*`, 배리언트 라벨 키가 모두 재측정되어 존재; `loadNoWgsl`/`loadNotZip`도 여전히 그대로).
- **재조사하는 사람을 위한 번들 레이아웃**: 헤더 c55 (불변), 로더/지속화 c51–c53, 검증기 + 레지스트리 빌더 c55, WebGPU 코드젠 c56, 포그 c9, **기본 팩 템플릿 c116** (c124에서 이동), BLOXD_ALPHA 발생지 c51/c52/c53/c55/c9. 청크 형식 메모: 이제 모든 청크가 ES 모듈이다 (`export const modules = {...}`) — c53에는 c52와 c53 양쪽의 모듈까지 들어 있다 — 번들을 텍스트 검색할 때 중요하다 (`1371` 같은 모듈 id는 어떤 청크도 아닌 *main*의 희소 모듈 배열에 산다).

## 79. 엔진 내부 v5: 텍스처 파이프라인과 46-심볼 `bloxdSp*` 네임스페이스

v4 §63의 3-배리언트 텍스처 코드젠이 같은 형태로 이어진다. 라이브 제너레이터 (c56) 에서 복원:

**배리언트 1 — 텍스처 팩 없음** (생성 블록 전체; `bloxdTextureSize`와 `bloxdTexel`은 스텁):

```wgsl
fn bloxdTextureSize(bloxdSpMipLevel: f32) -> vec2u {
        return vec2u(1u);
}
fn bloxdTexel(bloxdSpTextureId: u32, bloxdSpUv: vec2f, bloxdSpMipLevel: f32) -> vec4f {
        return vec4f(1.0);
}
```

**배리언트 2 — 아틀라스 경로** (게임에서의 기본): `bloxdTextureSize`는 `textureDimensions(textureAtlas0, u32(clamp(round(bloxdSpMipLevel), 0.0, f32(textureNumLevels(textureAtlas0) - 1u))))`를 반환하고, `bloxdTexel`은 로드 전에 면의 4분회전을 적용한다 — v4의 회전 미묘함 (v4 가이드 §57.4), 이제는 생성된 `bloxdSpTurned`에 대한 명시적 if-체인으로 풀어 쓰인다:

```wgsl
        // Each quarter turn clockwise the face shows its texture at reads the unturned texture at (v, 1 - u)
        var bloxdSpTurned = bloxdSpUv;
        if (bloxdSpTextureRotation == 1u) {
                bloxdSpTurned = vec2f(bloxdSpUv.y, 1.0 - bloxdSpUv.x);
        } else if (bloxdSpTextureRotation == 2u) {
                bloxdSpTurned = 1.0 - bloxdSpUv;
        } else if (bloxdSpTextureRotation == 3u) {
                bloxdSpTurned = vec2f(1.0 - bloxdSpUv.y, bloxdSpUv.x);
        }
```

(그 발췌의 `bloxdSpTextureRotation` 이름은 입력 4조의 회전 멤버에 대한 엔진 자신의 저장소다 — v4 §63.2의 전달 경로, 역할은 불변.) **배리언트 3 — 커스텀 텍스처 팩 텍스처** — 레이어 아틀라스의 텍스처별 셀을 `textureLoad(<atlas>, min(bloxdSpCellAt * bloxdSpSize + bloxdSpAt, <dims> - 1u), bloxdSpLevel)`로 샘플링하며, 팩 자기 텍셀용 `bloxdSpOwnTexel` 경로가 딸려 있다.

## 82. 완전한 v5 엔진 헤더, 그대로

§67의 성과물을 v5용으로 재측정한 것: 로더가 모든 팩 앞에 붙이는 정확히 그 텍스트, 라이브 프로덕션 번들 (`ab90qa`, 청크 c55, 템플릿을 여섯 개의 라이브 삽입값 — `apiVersion`과 `bloxdPackInputs`를 거치는 다섯 개의 uniform 판독 — 으로 렌더링) 에서 복원했다. 디코딩 8,954 바이트, 208 줄. 바꿔 말한 것은 하나도 없다:

```wgsl

// The Bloxd shader pack API, apiVersion 5. Read-only, prepended to all packs.

const bloxdPi: f32 = 3.1415926535898;
const bloxdTau: f32 = 6.2831853071796;

// Blocks along each side of a chunk.
const bloxdChunkSize: i32 = 32;

// These functions return the same value for the entire frame.

// The camera's render position.
fn bloxdEyePosition() -> vec3f {
    return bloxdPackInputs.eyePosition;
}

// Integer distance, in blocks: render position + this offset = world position.
// Changes as the player travels, so render positions stay close to 0,0,0.
// See bloxdWorldPosition for one way to use it.
fn bloxdRenderOffset() -> vec3i {
    return bloxdPackInputs.renderOffset;
}

// The unit vector towards the sun, in world orientation; 0 when there's no sun.
fn bloxdSunDirection() -> vec3f {
    return bloxdPackInputs.sunDirection;
}

// Seconds since the page loaded. As an f32, it has sub-millisecond precision
// for the first 4.5 hours. Get a recurring timer using bloxdSeconds() % period.
fn bloxdSeconds() -> f32 {
    return bloxdPackInputs.seconds;
}

// Whether block and sky lighting is on. When it's off, BloxdLightIn's
// blockLight and heldLight are 0, and its skyLight and light colours are 1.
fn bloxdLit() -> bool {
    return bloxdPackInputs.lit != 0u;
}

// What kind of block, item or lifeform a face is. Any number of flags may be
// set, possibly even none. For example, sandstone is sand and rock.
struct BloxdFlags {
    opaque: bool,     // Opaque blocks, i.e. full cubes with no gaps or holes.
    emissive: bool,   // Blocks that emit light, e.g. lava and glowing ores.
    vegetation: bool, // Leaves, grass blocks and leafy plants, e.g. tall grass.
    dirt: bool,       // Soil, grass blocks included. Rocky Dirt is rock too.
    sand: bool,       // Sand, Red Sand and every sandstone, which is rock too.
    rock: bool,       // Stone variants, and more, e.g. gravel, ores and magma.

    // Drawn as block models, so never part of terrain or flagged as opaque.
    slab: bool,       // Half blocks.
    stairs: bool,     // Stairs and corner stairs.
    flat: bool,       // Planes, e.g. tall grass, flowers, crops and cobwebs.

    placed: bool,     // Blocks placed as part of chunks. Not items or vehicles.
    held: bool,       // Items in a hand, in first or third person.
    dropped: bool,    // Dropped items, on the ground, on a belt or in a pipe.
    thrown: bool,     // Items in flight, e.g. snowballs, arrows and rockets.

    lifeform: bool,   // Players, mobs and NPCs. Includes armour and cosmetics.
}

// Convert a render position to a world position, with possible f32 inaccuracy.
fn bloxdWorldPosition(position: vec3f) -> vec3f {
    return position + vec3f(bloxdRenderOffset());
}

struct BloxdVertexIn {
    position: vec3f,      // Render position.
    normal: vec3f,        // Unit vector pointing away from the face.
    localPosition: vec3f, // A model's local coordinates. 0 for terrain/liquid.
    flags: BloxdFlags,    // What kind of block, item or lifeform.
}

struct BloxdVertex {
    position: vec3f,      // The render position output.
}

struct BloxdSurfaceIn {
    colour: vec3f,        // RGB colour = texture * tint * ambient occlusion.
    alpha: f32,           // Opacity.

    // Enchanted items and armour only, all 0 for anything else.
    enchantTier: u32,     // 1-5 for Tier 1-5.
    enchantColour: vec4f, // RGB enchant colour, and its animated alpha.
    enchantSpeed: f32,    // How fast the pattern moves, faster at higher tiers.

    // Players and mobs only, 0 for anything else: RGB overlay colour, e.g. the
    // red flash when hurt, and its alpha. bloxdLitColour mixes it into colour.
    overlayColour: vec4f,

    // These mean the same as in BloxdVertexIn, after the vertex hook.
    position: vec3f,      // Render position.
    normal: vec3f,        // Unit vector pointing away from the face.
    localPosition: vec3f, // A model's local coordinates. 0 for terrain/liquid.
    flags: BloxdFlags,    // What kind of block, item or lifeform.

    // These are all 0 if the face has no texture. Most models use textureId 0.
    textureId: u32,       // This face's texture. Compare with bloxdTextureId*.
    textureRotation: u32, // Quarter turns clockwise, which bloxdTexel applies.
    uv: vec2f,            // The texture spans 0-1. fract(uv) is drawn.
    mipLevel: f32,        // Texture mipmap level. 0 = full size, 1 = half, etc.
}

struct BloxdSurface {
    colour: vec3f,        // RGB colour output.
#ifdef BLOXD_ALPHA
    alpha: f32,           // Opacity output.
#endif
    emission: vec3f,      // Emissive RGB, added after lighting, before fog.
    enchantColour: vec4f, // Enchant output, mixed in by bloxdLitColour.
    overlayColour: vec4f, // Overlay output, mixed in by bloxdLitColour.
}

// blockLight, skyLight and heldLight are 0-1, from the 0-15 light levels on an
// ease-out curve, e.g. 6->0.45, 12->0.92. They all exclude ambientLightColour.
// bloxdLitColour lights a surface from these as the engine does.
struct BloxdLightIn {
    litColour: vec3f,  // Lit and enchanted RGB colour, before emission and fog.
    directional: f32,  // Summed Lambert from directional lights; 0 if none.
    diffuse: vec3f,    // The material's RGB response to directional light.
    emissive: vec3f,   // The material's RGB glow, added to directional light.
    ambient: vec3f,    // RGB ambient colour, added to directional light.
    blockLight: vec3f, // RGB block light; 0 when !bloxdLit().
    skyLight: f32,     // Sky light; 1 when !bloxdLit().
    ambientLightColour: vec3f, // Minimum RGB light; 1 when !bloxdLit().
    skyLightColour: vec3f, // RGB colour of skyLight; 1 when !bloxdLit().
    heldLight: vec3f,  // RGB held light; 0 when !bloxdLit() or no light held.
    fogColour: vec3f,  // The game's RGB fog colour; 0 when the game has no fog.
    fogAlpha: f32,     // 0 = no fog, 1 = only fogColour.

    // These are the same as in BloxdSurfaceIn.
    position: vec3f,      // Render position.
    normal: vec3f,        // Unit vector pointing away from the face.
    localPosition: vec3f, // A model's local coordinates. 0 for terrain/liquid.
    flags: BloxdFlags,    // What kind of block, item or lifeform.
    textureId: u32,       // This face's texture. Compare with bloxdTextureId*.
    textureRotation: u32, // Quarter turns clockwise, which bloxdTexel applies.
    uv: vec2f,            // The texture spans 0-1. fract(uv) is drawn.
    mipLevel: f32,        // Texture mipmap level. 0 = full size, 1 = half, etc.
}

struct BloxdLight {
    colour: vec3f, // RGB colour output.
}

struct BloxdOpaqueBehind {
    hit: bool,       // False where nothing opaque is behind (sky).
    position: vec3f, // The render position; 0 when !hit.
    distance: f32,   // From the camera; 0 when !hit.
}

fn bloxdDefaultVertex(vertex: BloxdVertexIn) -> BloxdVertex {
    return BloxdVertex(vertex.position);
}

fn bloxdDefaultSurface(surface: BloxdSurfaceIn) -> BloxdSurface {
    return BloxdSurface(
        surface.colour,
#ifdef BLOXD_ALPHA
        surface.alpha,
#endif
        vec3f(0.0),
        surface.enchantColour,
        surface.overlayColour,
    );
}

// Apply this fragment's fog to colour, as the engine does.
fn bloxdApplyFog(colour: vec3f, light: BloxdLightIn) -> vec3f {
    return mix(colour, light.fogColour, light.fogAlpha);
}

// How the face's material and angle light it: directional light on its
// diffuse colour, plus its emissive and ambient terms, clamped to 0-1.
fn bloxdShading(light: BloxdLightIn) -> vec3f {
    let diffuse = light.directional * light.diffuse;
    return saturate(diffuse + light.emissive + light.ambient);
}

// The world's light at this fragment: the brightest of block, sky and held
// light, none below ambientLightColour.
fn bloxdWorldLight(light: BloxdLightIn) -> vec3f {
    let ambientLight = light.ambientLightColour;
    let blockLight = ambientLight + light.blockLight * (1.0 - ambientLight);
    let skyLight = mix(ambientLight, light.skyLightColour, light.skyLight);
    let heldLight = ambientLight + light.heldLight * (1.0 - ambientLight);
    return max(max(blockLight, skyLight), heldLight);
}

// The surface's colour lit as the engine does, before emission and fog:
// mixed with overlayColour, then bloxdShading, then mixed with
// enchantColour, then bloxdWorldLight.
fn bloxdLitColour(surface: BloxdSurface, light: BloxdLightIn) -> vec3f {
    let overlay = surface.overlayColour;
    let overlaid = mix(surface.colour, overlay.rgb, overlay.a);
    let shaded = bloxdShading(light) * overlaid;
    let enchant = surface.enchantColour;
    let enchanted = mix(shaded, enchant.rgb, enchant.a);
    return max(enchanted * bloxdWorldLight(light), vec3f(0.0));
}

fn bloxdDefaultLight(surface: BloxdSurface, light: BloxdLightIn) -> BloxdLight {
    let lit = bloxdLitColour(surface, light);
    return BloxdLight(bloxdApplyFog(lit + surface.emission, light));
}
```

위의 모든 훅 서명, 구조체, 상수, 주석은 하중을 지는 부재다: 라이브 검증기가 파싱하는 것, 코드 제너레이터가 앞에 붙이는 것, 당신의 팩이 컴파일되는 대상이 바로 이것이다. v4 헤더 ([v4 마이그레이션 가이드](v4.md)의 §67) 와 비교해 보면 v5가 한 화면에 드러난다: 상단의 `bloxdChunkSize`와 `bloxdLit()`, 비트 상수를 대체하는 `BloxdFlags` 구조체, 입력 구조체의 `localPosition`과 인챈트/오버레이 필드, 새 출력 둘, 그리고 `bloxdDefaultLight` 앞의 조명 헬퍼 세 개.
