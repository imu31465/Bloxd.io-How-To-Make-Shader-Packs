# 着色器包能做到什么、做不到什么

> 目标API: 5 · 目标构建: `ab90qa` (2026-11-03, 生产环境) · 状态: Verified (已移植到当前API — 建议实机复核)

一页讲清着色器包的写实化天花板：当前 API 能到达哪里、原理上做不到什么、什么是有条件的、限制为何存在、以及最接近的替代手段。动手之前先在这里核对预想。

## 当前 API 能做到什么

- **逐面控制颜色、透明度与发光** —— 三个 `Surface` 钩子为地形、液体和模型返回颜色 (外加条件性的 alpha 与 emission)
- **完整重建光照** —— 三个 `Light` 钩子与光照 API (`bloxdShading()` / `bloxdWorldLight()` / `bloxdLitColour()`) 把引擎自己的配方作为可组合的函数公开 ([光照 API](../api/lighting.md))
- **实时跟随方块编辑的投影风阴影** —— `skyLight` 是体素级的天空遮蔽数据；提升逆变换 + 阈值切割即可变成树下与屋檐下清晰的阴影 ([阴影](shadows.md))
- **读取游戏自己的纹理** —— `bloxdTexel()` 以与引擎采样器完全相同的方式采样方块纹理图集与模型自有纹理 ([纹理 API](../api/texture-api.md))
- **逐模型特效** —— `flags` 直接告诉你「这是手持物」「这是掉落物」「这是玩家」「这是台阶」 ([flags](../api/flags.md))；`localPosition` 提供模型局部坐标 ([输入输出结构体](../api/structures.md))
- **附魔辉光与受击闪光覆盖** —— `enchantTier` / `enchantColour` / `enchantSpeed` 与 `overlayColour` 均可读取、可覆写 ([附魔效果](../recipes/enchant-effects.md))
- **时间与动画** —— `bloxdSeconds()`、世界坐标与太阳方向驱动运动 ([时间与动画](../recipes/animation.md))

## 当前 API 做不到什么

| 表现 | 原因 |
|---|---|
| 像素级阴影贴图 (随太阳旋转的影、半影) | 深度纹理不可引用 (液体限定的 `bloxdOpaqueBehind()` 仅为几何信息，不能用作阴影贴图)。光线遮蔽判定也不输入钩子 |
| SSAO | 无法访问场景深度 (仅有网格烘焙的顶点 AO；液体限定深度不能用于 SSAO) |
| SSR (反射) | 场景色取不到。仅能以菲涅尔混空色的拟似表现 |
| 泛光 / 眩光 | 无挂钩后处理的钩子 |
| 景深、色散、颗粒 | 需要全屏后处理 |
| 体积光 (上帝光) | 同上 |
| 自定义 PBR 贴图 (法线 / 粗糙度 / 金属度纹理) | 包不能添加自己的纹理——API 只能经 `bloxdTexel()` *读取*游戏现有纹理，而那些是普通颜色纹理，没有 PBR 通道。拟似 PBR 响应只能从颜色亮度加 `flags` 估算 ([纹理 API](../api/texture-api.md)) |
| 水下折射 | 场景色取不到。液体限定深度 (`bloxdOpaqueBehind()`) 可做厚度吸收与底面投影 ([让水看起来自然](water.md)) |
| 水下幕 (蓝色调) 的去除与变更 | 幕为「相机所在液体方块定义 color/alpha」生成的 emissive 全屏 quad，在钩子管线之外 (最前面) 绘制，包改不了颜色也改不了浓度 |
| 水下直接检测 | 无表示相机入水的输入，且水下 fogStart / fogEnd / fogColour 不变，因此也没有从 fogAlpha 等推定的可靠方法 |
| 改动天空、云或太阳圆盘本身 | 钩子逐面运行于地形 / 液体 / 模型几何上；天空盒不属于任何钩子管线 |

## 有条件的能力

- **顶点动画与 `discard`** —— 仅在游戏定义显式携带 `shaderPackPolicy: "allow"` 的标题可用；其余标题一律 `BLOXD_STRICT` 会把这些钩子编译掉 ([各游戏的着色器适用策略](../internals/policy.md))
- **场景深度 (`bloxdOpaqueBehind()`)** —— 仅液体钩子可用，且需要 `BLOXD_SCENE_DEPTH`；地形与模型钩子无深度访问 ([函数](../api/functions.md))
- **`bloxdTexel()` / `bloxdTextureSize()`** —— 仅 surface 与 light 钩子可用，且仅限管线有纹理的配置；无纹理的配置会把它们编译成返回白色的桩 ([纹理 API](../api/texture-api.md))
- **地形 alpha (`BLOXD_ALPHA`)** —— 仅在定义了它的变体中可用 ([变体与守卫](../getting-started/variants.md))

## 这些限制为何存在

「真正的」后处理着色器所需的四类输入在结构上缺失：

1. **没有场景颜色** —— 钩子在各面绘制时运行；没有可读取的帧缓冲纹理，因此 SSR、折射以及一切「我身后是什么」的派生计算都无从谈起
2. **没有场景深度** —— 除液体限定的 `bloxdOpaqueBehind()` 几何探针外；SSAO 与阴影贴图需要完整深度缓冲
3. **没有后处理阶段** —— 帧合成完成后没有任何钩子运行，泛光、景深、色散、颗粒与上帝光都没有入口
4. **没有天空访问** —— 天空盒、云与太阳圆盘在钩子管线之外绘制，除 `bloxdSunDirection()` 外没有任何输入描述它们

水下幕是同一结构的特例：它是从相机所在液体方块定义生成的 emissive 全屏 quad，绘制在最前面——在所有钩子管线之外。

## 最接近的替代手段

| 想要 | 包侧最接近的做法 |
|---|---|
| 反射 | 向近空色做菲涅尔加权混合 + 太阳闪光 ([让水看起来自然](water.md)) |
| PBR 材质 | 基于亮度的镜面/粗糙度估算 + 基于 `flags` 的材质分类 ([颜色](../recipes/colors.md)、[写实化](../recipes/realism.md)) |
| 泛光 / 辉光 | emission 输出——货真价实的加法辉光，但是逐面的，不是后处理模糊 ([发光](../recipes/emission.md)) |
| 环境光遮蔽 | 已烘焙进 `surface.colour` 的网格顶点 AO；skyLight 压暗可兼作大尺度 AO ([阴影](shadows.md)) |
| 水深吸收 | 液体钩子内的 `bloxdOpaqueBehind()` 厚度 + 底面投影 ([液体](../recipes/liquids.md)) |
| 水下氛围 | 接受色幕；对幕后可见的内容做文章 (地形/液体在水下仍正常渲染) |

## 阴影的真相 —— 「树影」做得出来

上表中不可能的只是**随太阳旋转的像素级阴影贴图**。引擎从一开始就在算「影」，那就是 `skyLight`。网格侧 LightEngine 运行类 Minecraft 算法：

1. **纵列扫描**：每 (x,z) 列自上而下扫描。天空来光从 15 开始，**不透明方块处归 0**，此后按 `lightFilter` (空气 1 / 水 3 / 不透明 15) 衰减下降
2. **BFS 泛洪**：向 6 邻横向扩散 (每格 -1) —— 这正是影缘变软的正体。半径 r 遮蔽物下的原始值为 (15-r)/15
3. blockLight (火把等) 为 RGB 3 通道 (4bit 打包) 的另一路 BFS

于是 `l.skyLight` 不是单纯的亮度参数，而是**「该处能否看见天空」的体素分辨率遮蔽数据 = 阴影贴图**。树下、屋檐下、室内数值本已偏低，经顶点插值平滑到达。放置/破坏方块即刻重算 = **实时跟随的阴影**。原版仅以 `mix(环境色, 空色, skyLight)` 「轻混」使用。

正确的工具是[阴影](shadows.md)中的两步 (**提升逆变换恢复原始值 → 阈值 `smoothstep` 二值化**；`th = 1 - r/15` 直接拨定「视为阴影的遮蔽半径」) 加上**以 sky 门控太阳直射光** (太阳只到达看得见天空之处 = 投影的正体)，再以向阳暖色 / 阴影冷色染色构成。

**如实声明的限制**：该阴影以「上方天空」为基准，**不随太阳移动旋转**。分辨率为方块级 (柔边来自 BFS 扩散)。引擎光照模板中仍残留闭合的 `var shadow: f32 = 1.;` 阴影贴图桩 (恒为 1.0 = 无效)，可解读为「计划中的像素级旋转阴影」的痕迹。若非要像素级旋转阴影，只剩 API 之外的路线 (如 userscript GLSL 注入，有规则风险)。

## 水下环境的实情

水中的外观由 3 层构成：

| 层 | 内容 | 包可否操作? |
|---|---|---|
| ① 地形/液体绘制 | 钩子可加工。light 钩子在水下也照常调用 | 可 (在幕之下生效) |
| ② 液体定义色幕 | 相机所在液体方块定义 color/alpha 的 emissive 全屏 quad，绘制在最前面。游戏设置 `cameraTint` 有则优先 | 不可 (颜色浓度都改不了) |
| ③ cameraTint | 游戏设置 | 不可 |

实用要点：包在水下也继续工作 / 幕去不掉 / 水下不可分支 (fogStart / fogEnd / fogColour 在水下不变，fogAlpha 也检测不到)。
