# パックの構成

> 対象API: 5 · 対象ビルド: `v98qt8` · 検証状況: Verified

## 配布形態

- **配布形態**: `.zip` 1つ、またはフォルダ (フォルダ読み込みはデスクトップ版ブラウザのみ)
- **中身**: `pack.json` 1つ (パックの最上位に配置。大文字小文字は区別されない) + `.wgsl` ファイル 1〜256個
- 複数の `.wgsl` は連結されて1モジュールとして扱われるため、分割・ディレクトリ分けは自由。ファイル名に制約は無い。連結は**パス名の辞書順**で行われる (モジュールスコープの宣言は順序非依存なので通常は無関係だが、`var` の初期化順序に依存する書き方をした場合のみ効く)。`.wgsl` 以外のファイル (README等) は無視される

## サイズ・形式の上限

| 項目 | 上限 | 超過時のメッセージ |
|---|---|---|
| zip サイズ | 32 MB | `The zip is over 32 MB.` |
| zip エントリ数 | 1,024 | `The zip has more than 1024 entries.` |
| `pack.json` のサイズ | 64 KB (UTF-8) | `pack.json is over 64 KB.` |
| `.wgsl` ファイル数 | 256 | `The pack has more than 256 .wgsl files.` |
| `.wgsl` ソース合計 | 256 KB (UTF-8) | `The pack's .wgsl files are over 256 KB in total.` |
| zip 形式 | zip64・分割・暗号化は不可。圧縮は store / deflate のみ、重複パスは不可 | それぞれ専用メッセージで拒否 |

全ファイルは有効な UTF-8 である必要があります。

## ZIP化のコツ

全ファイルが共通する 1 階層のルートフォルダに収まっている zip は、そのプレフィックスが自動的に剥がされます (macOS の「フォルダを圧縮」でできる zip もそのまま OK。`__MACOSX` / `._` で始まるファイル / `.DS_Store` 等の OS ゴミは自動で除外される)。

ただしルート階層に余分なファイルが混ざると最上位判定を失うため、確実なのはフォルダの中に入って `pack.json` と `.wgsl` を直接指定して固めること (`pack.json` が zip 直下に来ることを確認する)。
