# API v1

> État : **Historical** — la première époque du mécanisme de packs de shaders. Chaque pack v1 est rejeté par le jeu actuel.

La v1 était la première API de packs de shaders. La v2 a renommé les identifiants en bloc (table du §32 du [guide v2](v2.md)), donc l'intérêt principal de connaître le vocabulaire v1 est **lire les anciennes distributions et les vieux guides communautaires**.

## Vocabulaire v1 (renommé en v2)

| v1 | v2 et suivantes |
|---|---|
| `bloxdTime()` | inchangé (devenu `bloxdSeconds()` en v3) |
| `bloxdOriginOffset()` | inchangé (devenu `bloxdRenderOffset()` en v3) |
| `bloxdFaceBlock(position, normal)` | inchangé (supprimé en v3) |
| `fogFactor` | `fogVisibility` (devenu `fogAlpha` en v5, inversé) |
| `engineColour` | inchangé (supprimé en v5 — restructuré en `litColour` et `bloxdLitColour()`) |
| — | `blockId` (ajouté en v2, devenu `blockFlags` en v3) |

Les hooks étaient terrain / liquide × vertex / surface — **6 hooks**, pas de hooks de lumière (les hooks de lumière ne sont devenus partie du modèle par défaut qu'en v5). L'identification des blocs reposait uniquement sur une conjecture à partir de la couleur de texture ; `blockId` / `blockFlags` / `flags` n'existaient pas encore.

## Migration v1 → v2

Le renommage intégral fait que la conversion n'est pas mécanique. Lisez le [guide de migration v2](v2.md) depuis le début :

1. [§31 Le sort des packs v1](v2.md)
2. [§32 Renommage des identifiants (la table)](v2.md)
3. [§33 Où sont passés les champs supprimés](v2.md)
4. [§37 Checklist v1 → v2](v2.md)

Appliquez ensuite v3 → v4 → v5 dans l'ordre ([le chemin rapide](index.md#chemin-rapide-vers-une-checklist)).
