## 31. v1 पैकों का भाग्य (पहले निष्कर्ष)

खेल manifest `apiVersion` का **ठीक-ठीक 2 से मेल** माँगता है। v1 पैक लोड `This pack is for shader pack API version 1. Bloxd supports version 2.` (i18n कुंजी `shaderPack:loadWrongApiVersion`) से अस्वीकृत होता है। v1/v2 का **समानांतर समर्थन नहीं** है। इंजन सहेजे गए पैकों का `validation.headerVersion` (हेडर के पूर्ण पाठ का हैश) भी पुनः जाँचता है, अतः इंजन अद्यतन पर सहेजे पैक स्वतः "needs re-check" चिह्नित होने का तंत्र v1 जैसा ही है।

## 33. हटाए गए फ़ील्ड कहाँ चले गए

v1 में `time` / `eyePosition` / `sunDirection` / `originOffset` संरचना फ़ील्ड थे। v2 में **ये फ़ील्ड हटा दिए गए; बदले में इंजन uniform (`bloxdPackInputs`) पढ़ने वाले हेडर फ़ंक्शन** प्रयोग होते हैं। फ़ंक्शन uniform को सीधे पढ़ते हैं, अतः **इन्हें हुकों के बाहर मॉड्यूल-स्कोप फ़ंक्शनों से और vertex हुकों से भी बुलाया जा सकता है**।

| v1 | v2 |
|---|---|
| `s.time` / `v.time` / `l.time` | `bloxdTime()` |
| `s.sunDirection` / `l.sunDirection` | `bloxdSunDirection()` |
| `s.eyePosition` / `l.eyePosition` | `bloxdEyePosition()` |
| `s.originOffset` / `l.originOffset` | `bloxdOriginOffset()` |

| `vec3i(floor(pos - normal*0.5)) + originOffset` | `bloxdFaceBlock(pos, normal)` |

## 34. नई सुविधा ①: `blockId` (प्रति-खंड शेडिंग)

तीनों संरचनाओं `BloxdVertexIn` / `BloxdSurfaceIn` / `BloxdLightIn` में `blockId: u32` जोड़ा गया। यह **फलक के स्वामी खंड का ID** (0–65535) है और उसी फलक में स्थिर रहता है (`@interpolate(flat)` से पारित)। इसे टेक्सचर रंग से स्वतंत्र खंड-प्रकार पहचान में प्रयोग करें। पर ID-से-खंड-प्रकार संगति तालिका इंजन के भीतर रहती है और पैक से दिखाई नहीं देती, अतः **कौन ID किस खंड का है, यह दुनिया में मापकर, या नीचे दिए संदर्भ से जाँचा जा सकता है**। भीतर-भीतर यह ID शीर्ष-रंग के α (निचले 8 bit) और अभिलंब के w (ऊपरी 8 bit) — कुल 16 bit — में पकाकर ले जाया जाता है; 65535 की सीमा इसी पथ-चौड़ाई से आती है। blockId तंत्र स्वयं केवल सक्रिय शेडर-पैक होने पर सक्रिय होता है (बिना पैक wire का गंतव्य padding ही रहता है, पर भाग II की संरचना-परिभाषाओं के भीतर से यह अंतर दिखता नहीं)।

**संदर्भ**: लेखक गेम-प्रविष्टि सूची [Bloxd-Entries-Data](https://github.com/imu31465/Bloxd-Entries-Data) पर प्रकाशित करता है (`entries.json`: id ↔ खंड-नाम तालिका; `Furnace|meta|rot2` जैसे घूर्णन/meta रूप भी पृथक ID हैं)। मिलान गेम अपडेट से बदल सकते हैं — पक्की जाँच वास्तविक गेम में करें।

आम खंडों के उदाहरण (entries.json से, 2026-10-18 तक; केवल कम id वाले टेरेन परिवार दिखाए गए):

| ID | खंड नाम | ID | खंड नाम |
|---|---|---|---|
| 0 | Air | 15 | Maple Wood Planks |
| 1 | Unloaded | 28 | Stone |
| 2 | Dirt | 29 | Messy Stone |
| 3 | Messy Dirt | 31 | Smooth Stone |
| 4 | Grass Block | 126 | Water |
| 5 | Sand | 128 | Bricks |
| 6 | Clay | 139 | Ice |
| 7 | Gravel | 147 | Bedrock |
| 8 | Snow | 149 | Cactus |
| 9 | Maple Log | 1491 | Lava |

entries.json में औज़ार आदि गैर-खंड प्रविष्टियाँ भी हैं, पर टेरेन / तरल हुकों तक केवल खंड-परिवार की id ही पहुँचती है।

### R-F. blockId से प्रति-खंड-प्रकार रंगत

```wgsl
fn blockTint(blockId: u32) -> vec3f {
    // जैसे: प्रस्तर-जैसे id (उच्च बिट प्रतिरूप) को शीतल झुकाएँ
    let stripe = f32((blockId >> 4u) & 1u);
    return mix(vec3f(1.0), vec3f(0.85, 0.95, 1.0), stripe * 0.5);
}

fn bloxdTerrainSurface(surface: BloxdSurfaceIn) -> BloxdSurface {
    var result = bloxdDefaultSurface(surface);
    result.colour *= blockTint(surface.blockId);
    return result;
}
```

### R-G. blockId का दुनिया में मापन — bit-समतल प्रदर्शन पैक

संगति तालिका में न होने वाले खंडों की id दुनिया में जाँचने की डिबग रेसिपी। आगे के `plane` स्थिरांक को `0, 1, 2, …` से बदलते हुए जाँचने वाले खंड के फलक का रंग पढ़ें।

```wgsl
const plane: u32 = 0u;

fn bloxdTerrainSurface(s: BloxdSurfaceIn) -> BloxdSurface {
    var out = bloxdDefaultSurface(s);
    let d = (s.blockId >> (plane * 3u)) & 7u;
    var palette = array<vec3f, 8>(
        vec3f(0.0, 0.0, 0.0), vec3f(1.0, 0.0, 0.0), vec3f(0.0, 1.0, 0.0), vec3f(1.0, 1.0, 0.0),
        vec3f(0.0, 0.0, 1.0), vec3f(1.0, 0.0, 1.0), vec3f(0.0, 1.0, 1.0), vec3f(1.0, 1.0, 1.0));
    out.colour = palette[d];
    return out;
}
```

फलक का रंग blockId के 3 bit सीधे RGB में दिखाता है (काला = 0 / लाल = 1 / हरा = 2 / पीला = 3 / नीला = 4 / मैजेंटा = 5 / सियान = 6 / श्वेत = 7)। एक बार देखने पर octal का एक अंक पढ़ा जाता है। p0 → p3 क्रम में 3, 2, 7, 2 पढ़ा जाए तो ऊपरी अंकों से बना octal 2723 = 1491 id है (Lava)। कम id वाले टेरेन परिवार दो देखने (p0, p1) में पूरे हो जाते हैं। केवल surface हुक से बना है, अतः strict शीर्षकों में भी चलता है।

### R-H. केवल पत्तियों को झुलाना — blockId से vertex हुक सीमित करना

R7 पवन रेसिपी ([रेसिपी](../recipes/)) पूरे टेरेन को लहराती है, पर vertex हुक भी `blockId` पढ़ सकता है, इसलिए लक्ष्य केवल पत्ती-खंडों तक सीमित किया जा सकता है। id सूची और WGSL सरणी (2026-10-18 के मापन तक; 22 प्रकार — Pine / Aspen / Maple / Jungle / Plum / Cedar / Palm / Autumn Maple / Fallen Maple / Pear / Cherry / Fallen Cherry / Spectral / Mango / फल-रूप / Autumn Aspen):

```wgsl
const LEAF_IDS = array<u32, 22>(
    100u, 101u, 102u, 103u, 491u, 492u, 493u, 653u, 655u, 911u,
    1226u, 1227u, 1636u, 1969u, 2019u, 2020u, 2021u, 2022u, 2023u,
    2024u, 2025u, 2085u);

// vertex हुक strict शीर्षकों में स्वतः निष्क्रिय होते हैं (§36 देखें)
#ifndef BLOXD_STRICT

fn sp_isLeaf(id: u32) -> bool {
    for (var i = 0u; i < 22u; i++) {
        if (LEAF_IDS[i] == id) { return true; }
    }
    return false;
}

fn bloxdTerrainVertex(v: BloxdVertexIn) -> BloxdVertex {
    var out = bloxdDefaultVertex(v);
    if (sp_isLeaf(v.blockId)) {
        let wp   = bloxdWorldPosition(v.position);
        let t    = bloxdTime();
        // विस्थापन विश्व-स्थिति का सुचारु फ़ंक्शन रखें। विश्व में उसी बिंदु की ओर इशारा
        // करने वाले साझा शीर्ष वही मान से हिलते हैं, अतः फलक कभी नहीं उखड़ते ([रेसिपी](../recipes/) R7 — वही सिद्धांत)
        let sway = sin(wp.x * 0.9 + t * 1.7) * cos(wp.z * 0.7 + t * 1.1);
        out.position.x += sway * 0.045;
        out.position.z += sway * 0.030;
    }
    return out;
}

#endif
```

- id सूची इंजन अपडेट के साथ बढ़ती है (मापन के दौरान ही एक नए बिल्ड में 50 खंड-प्रकार जुड़े)। निरंतर प्रयोग के लिए [Bloxd-Entries-Data](https://github.com/imu31465/Bloxd-Entries-Data) या R-G के bit-समतल प्रदर्शन से अतिरिक्त id जाँचकर सरणी में जोड़ें
- `Fallen Maple Leaves` (655) / `Fallen Cherry Leaves` (1227) ज़मीन पर बिछने वाली अठोस पत्तियाँ हैं। हिलाने पर वे ज़मीन से उठती दिखती हैं, इसलिए इन्हें सरणी से बाहर रखना भी एक विकल्प है
- strict शीर्षकों में vertex हुक पूरी तरह निष्क्रिय होता है, पर ऊपर जैसा guard हो तो पैक बस "झुलना बंद कर देता है" — fragment-पक्ष के प्रभाव जीवित रहते हैं

## 35. नई सुविधा ②: `BLOXD_SCENE_DEPTH` और `bloxdOpaqueBehind()` (मुख्य)

v1 में संरचनात्मक रूप से असंभव गहराई-पहुँच **केवल तरल (liquid) प्रोग्रामों के लिए** खुल गई। रंग नहीं, पर **ज्यामिति — पीछे पड़े अपारदर्शी फलक की दूरी और स्थिति — उपलब्ध** है। प्ररूपी उपयोग मापी गई जल-मोटाई से अवशोषण-रंग परिकलन है।

उपयोग नियम:

| उपयोग | परिणाम |
|---|---|
| `bloxdLiquidSurface` / `bloxdLiquidLight` में अरक्षित आह्वान | ठीक (तरल वेरिएंटों में सदा परिभाषित) |
| `bloxdTerrainSurface` में अरक्षित आह्वान | त्रुटि। `#ifdef BLOXD_SCENE_DEPTH` से लपेटें |
| vertex हुकों में आह्वान | त्रुटि (केवल surface / light हुक) |

टेरेन हुकों में भी गहराई चाहें तो `#ifdef BLOXD_SCENE_DEPTH` से लपेटें (टेरेन हुक तरल प्रोग्रामों में पुनः प्रयुक्त होते हैं, अतः गहराई केवल तरल पक्ष पर जीवित रहती है)।

### R-E. जल-मोटाई अवशोषण (Beer-Lambert)

```wgsl
fn bloxdLiquidSurface(surface: BloxdSurfaceIn) -> BloxdSurface {
    var result = bloxdDefaultSurface(surface);
    let behind = bloxdOpaqueBehind();
    if (behind.found) {
        // जल-स्तंभ लंबाई = यहाँ से पीछे पड़े अपारदर्शी फलक तक
        let thickness = distance(behind.position, surface.position);
        // Beer-Lambert अवशोषण: लाल शीघ्र गिरता है, नीला दूर तक जाता है
        let absorb = exp(-thickness * vec3f(0.35, 0.14, 0.08));
        result.colour *= absorb;
    } else {
        // पीछे कुछ नहीं = गहरे जल के नीले की ओर खींचें
        result.colour = mix(result.colour, vec3f(0.05, 0.15, 0.30), 0.4);
    }
    return result;
}
```

अनुप्रयोग: मोटाई-आधारित अवशोषण/प्रकीर्णन, `behind.position` से तल के विश्व निर्देशांकों से तरंग-कॉस्टिक-ढंग के पैटर्न का प्रक्षेपण, जलपृष्ठ पर आकाश-प्रतिबिंब हेतु `found=false` से आकाश बनाम अवरोध का भेद, गहराई से चरणबद्ध झाग व मैलापन। गहराई-प्रतिलिपि पाइपलाइन बनने में विफल हो जाए तो "पीछे कुछ नहीं" पर सुरक्षित अवनति। गहराई टेक्सचर की तैयारी पेज के रेंडरर बनने के समय एक बार "सक्रिय पैक गहराई पढ़ता है या नहीं" से तय होती है, अतः **गहराई पढ़ने वाले पैक के प्रयोग में हमेशा पेज पुनः लोड करें**। पैक सक्रिय रखते हुए बिना पुनः लोड किए गहराई माँगी जाए तो कंसोल में एक बार `…reads scene depth on a page that didn't turn it on` चेतावनी आती है और गहराई टेक्सचर 1×1 विकल्प से बदल जाती है, जिससे `bloxdOpaqueBehind()` सदा `found = false` लौटाता है।

## 36. अन्य v2 परिवर्तन

- **हुक फॉलबैक**: `bloxdLiquidXxx` अपरिभाषित होने पर तरल प्रोग्राम टेरेन हुकों पर गिर जाते हैं। **केवल-टेरेन-हुक वाला पैक जल पर भी ज्यों का त्यों असर करता है**। अनभीष्ट हो तो तरल-पक्ष के हुक स्पष्ट रूप से परिभाषित करें।
- **`BLOXD_LIGHTING` फ़ील्ड-रक्षक अब अनावश्यक**: `blockLight` आदि सभी वेरिएंटों में हैं, अलिट होने पर डिफ़ॉल्ट (0 / 1 / श्वेत / 0) रखते हैं। `#ifdef BLOXD_LIGHTING` केवल प्रकाश परीक्षण हेतु प्रयोग करें। विद्यमान रक्षक रखने से कुछ नहीं बदलता।
- **`BLOXD_ALPHA` परिभाषा-शर्त बदली**: गैर-strict टेरेन वेरिएंटों और सभी तरल वेरिएंटों में परिभाषित, strict × टेरेन में अपरिभाषित। टेरेन हुकों में alpha लिखें तो रक्षक रखें।
- **संरचना का सीधा निर्माण निषिद्ध**: `BloxdLight(...)` जैसे कंस्ट्रक्टर आह्वान स्थैतिक सत्यापन में अस्वीकृत होते हैं। सदा `bloxdDefault*` से बदलें, या इनपुट की प्रतिलिपि प्रयोग करें।
- **`let _ =` से `_ =`**: WGSL त्याग-असाइनमेंट `_ = f();` वैध है, पर `let _ = f();` अस्वीकृत।
- **offInStrict**: vertex हुक की परिभाषि, या surface / light हुकों से पहुँच-योग्य `discard`, होने पर त्रुटि देने के बजाय पूरा पैक strict गेमों में स्वतः निष्क्रिय हो जाता है (सेटिंग्स UI में `shaderPack:offInStrict`; allow गेमों में फिर भी चलता है)। vertex हुकों और `discard` को `#ifndef BLOXD_STRICT` से लपेटें। ध्यान दें, आधिकारिक सेटिंग्स UI संदेश स्वयं निर्देश देता है "wrap what remains with `#ifndef BLOXD_STRICT`" — यह पद्धति केवल परंपरा नहीं, आधिकारिक अनुशंसा है।
- **फ़ॉग विस्तार**: LINEAR / EXP / EXP2 फ़ॉग विधाएँ कार्यान्वित हैं, पर गेम सेटिंग्स अब भी सदा LINEAR उपयोग करती हैं, इसलिए विद्यमान फ़ॉग विनिर्देश चलते रहते हैं। `fogColour` के अर्थ अब आधिकारिक रूप से प्रलेखित हैं (केवल पूर्णतः फ़ॉग-रहित दृश्यों में ही काला)।
- **अपरिवर्तित**: लिफ़्ट वक्र, 35% चैनल-फ़र्श, heldLight क्षय (`pow(lightDist, 0.75)`) और परिवेश-वृद्धि, सूर्य/चंद्र दिशा विनिर्देश, डिफ़ॉल्ट फ़ॉग रंग, समय-लपेटन (3600 सेकंड), दिशात्मक प्रकाश (अधिकतम 4), केवल Lite (WebGPU), सहेजने का तंत्र (IndexedDB), `mod` आरक्षित शब्द।

## 38. दूसरा सत्यापन चरण — ब्राउज़र का WGSL कंपाइलर अंतर्निहित पार्सर से कठोर है

गेम में पैक सत्यापन **2-चरणीय** है। पहला चरण स्थैतिक सत्यापन है (इंजन का अंतर्निहित JS पार्सर — हुक हस्ताक्षर, निषिद्ध वाक्यरचना, sceneDepth उपयोग जैसे पैक-विशिष्ट नियमों की जाँच), और दूसरा चरण ब्राउज़र सत्यापन है (संकलन परिणाम में संलग्न स्टब का वास्तविक WebGPU कार्यान्वयन से संकलन, त्रुटियों को पैक की स्रोत फ़ाइलों की पंक्तियों पर वापस मैप कर प्रदर्शित करना। UI का "Saved, but it won't run until you fix these errors" यही चरण है)। त्रुटि-प्रदर्शन के अंत में आया `(only in terrain)` जैसा प्रत्यय "उस त्रुटि वाले वेरिएंट की program किस्म" बताता है।

अंतर्निहित पार्सर WGSL के संक्रियक-बंधन (binding) नियम लागू नहीं करता, इसलिए **स्थैतिक सत्यापन पास करने वाला कोड ब्राउज़र में अस्वीकृत हो सकता है**। क्षति-प्रवण नियत पूर्णांक-हैश प्रतिरूप है:

| संक्रियक | परिणाम |
|---|---|
| `<<` `>>` | केवल एकल स्तर पर ही सीधे बंध सकते हैं। `a + b << c` त्रुटि है |
| `&` `^` `\|` | केवल एकल स्तर पर ही सीधे बंध सकते हैं। `a * b ^ c` त्रुटि है |
| `&&` `\|\|` | मिश्रण असंभव। `a && b \|\| c` त्रुटि है |

### कोष्ठक लगाने की विधि (NG / OK)

```wgsl
// NG — स्थैतिक सत्यापन पास, पर ब्राउज़र (Tint) अस्वीकृत करता है:
//     mixing '*' and '^' requires parenthesis
let h = a * 73856093u ^ b * 19349663u ^ c * 83492791u;

// OK — प्रत्येक गुणन कोष्ठकबद्ध (एक ही संक्रियक की श्रृंखला A ^ B ^ C स्वयं वाम-साहचर्य से वैध)
let h = (a * 73856093u) ^ (b * 19349663u) ^ (c * 83492791u);
```

इस गाइड में छपा कोड इस प्रतिरूप का नहीं है (`pack_hash3` का `+`/`*` मिश्रण और `h ^ (h >> 16u)` पहले से कोष्ठकबद्ध हैं, इसलिए विनिर्देश-अनुरूप)। पैक लिखें तो पहला और दूसरा — दोनों चरण — उत्तीर्ण कराएँ।
